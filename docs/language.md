# Կեռաս լեզվի նկարագրությունը

_Կեռասը_ Բեյսիկ լեզվից ածանցված լեզու է, որը պարզեցված ու հարմարեցված է 
որպես «Ծրագրավորման լեզվի նախագծում և իրականացում» թեմայով զրույցների 
գործնական աշխատանք։ Այն ներառում է ծրագրեր գրելու համար անհրաժեշտ 
նվազագույն միջոցներ՝ տիպեր ու ղեկավարող կառուցվածքներ։ Կեռասը, որպես
ուսումնական նախագիծ, ի սկզբանե նախատեսված է ընդլայնվելու համար։ Մեր
զրույցների ընթացքում կիրականացնենք դրա բազային տարբերակը, բայց նաև
կսահմանենք ընդլայնման պրոյեկտներ, որոնցից ամեն մեկը մի նոր հնարավորություն
կավելացնի լեզվին։

## Շարահյուսություն

Այսպիսով, Կեռասը ծրագիրը բաղկացած է ենթածրագրերից, որոնք կարող են 
կատարել և ֆունկցիայի, և պրոցեդուրայի դեր։ Բեկուսի-Նաուրի ընդլայնված
նոթագրությամբ կարող ենք ասել, որ.

```ebnf
Program = [ NewLines ] { Subroutine NewLines } EOF.
```

Ենթածրագրի սահմանումն ավելի հետաքրքիր է։ 

```ebnf
Subroutine = 'SUB' IDENT [ '(' [ ParameterList ] ')' ] ['AS' TypeName] Sequence 'END' 'SUB'.
```

Պարամետրերի ցուցակում ստորակետով իրարից անջատված տիպիզացված 
պարամետրերն են.

```
ParameterList = Parameter { ',' Parameter }.
Parameter = IDENT [ '[' ']' ] 'AS' TypeName.
```

Եթե պարամետրի անունի կողքին գրված է `[]`, ապա դա զանգված է։

Կեռաս լեզվի պարզ տիպերը երեքն են. տրամաբանական, իրական-թվային ու 
տեքստային.

```ebnf
TypeName = 'BOOL' | 'REAL' | 'TEXT'.
```

Սահմանումից նկատում ենք, որ ենթածրագրի թե պարամետրերի ցուցակը, և թե 
վերադարձվող արժեքի տիպը պարտադիր չեն։ Օրինակ, կարելի է գրել պարամետրեր 
չունեցող ֆունկցիա.

```basic
SUB RandomNumber AS REAL
  ' հաշվել մի պատահական թիվ
END SUB
```

Կամ կարելի է սահմանել պրոցեդուրա.

```basic
SUB PrintDate
  ' տպել այսօրվա ամսաթիվը
END SUB
```

Ֆունկցիա-ենթածրագրից արժեք վերադարձնելու համար հատուկ հրաման կամ
գործողություն նախատեսված չէ (ինչպես շատ լեզուների `return`-ը)։ Վերադարձվող
արժեքը պարզապես վերագրում ենք ենթածրագրի անունին։ Օրինակ, երկու թիվ 
գումարող ֆունկցիան կսահմանվի.

```basic
SUB Add(x AS REAL, y AS REAL) AS REAL
  LET Add = x + y
END SUB
```

Նկատենք նաև, որ ենթածրագրից կարելի է վերադարձնել միայն պարզ արժեքներ։

Ենթածրագրի մարմնում օգտագործեցինք `Sequence`, որը պարզապես նշանակում
է իրար հաջորդող հրամաններ։ Ահա կանոնը.

```ebnf
Sequence = NewLines { Statement NewLines }.
```

Այսինքն՝ հրամանների ցուցակը պետք է անպայման սկսվի մեկ կամ ավելի նոր
տողին անցման նիշերով, և ամեն մի հրամանից հետո էլ պետք է լինի գոնե
մեկ նոր տողին անցման նիշ։ Որտեղ.

```ebnf
NewLines = NEWLINE { NEWLINE }.
```

Հրամանները վեցն են. 

```ebnf
Statement = Dim | Let | If | While | For | Call.
```

Դրանք են՝ փոփոխական կամ զանգված սահմանող `DIM`-ը, վերագրման 
`LET`-ը, ճյուղավորման `IF`-ը՝ իր `ELSEIF` և `ELSE` ճյուղերով, նախապայմանով
ցիկլի `WHILE`-ը, և պարամետրով ցիկլի `FOR`-ը։

Փոփոխականներն ու զանգվածները սահմանվում են `DIM` հրամանով։ 

```ebnf
Dim = 'DIM' IDENT [ '[' Expression ']' ] 'AS' TypeName.
```

Եթե պարզ փոփոխական է սահմանվում, ապա տրվում է միայն անունն ու 
տիպը։ Իսկ զանգվածի համար (միաչափ) տրվում է նաև չափը. վերջինս
կարող է լինել ինչպես հաստատուն, այնպես էլ կատարման ժամանակ 
հաշվարկվող թվային արտահայտություն։ Արտահայտության արժեք
պետք է լինի դրական թիվ, որի ամբողջ մասով որոշվում է տարրերի
քանակը։

Վերագրման հրամանը փոփոխականին կամ զանգվածի տարրին նոր արժեք 
է վերագրում։ 

```ebnf
Let = 'LET' IDENT [ '[' Expression ']' ] '=' Expression.
```

Նկատենք, որ `LET` բառն այստեղ կոսմետիկ դեր է կատարում։ Լեզվի 
զարգացման վարժություններում կառաջարկենք այն դարձնել ոչ պարտադիր։

Ճյուղավորման հրամանը.

```ebnf
If = 'IF' Expression 'THEN' Sequence 
     { 'ELSEIF' Expression 'THEN' Sequence }
     [ 'ELSE' Sequence ]
     'END' 'IF'.
```

Այստեղ սահմանված է, որ `ELSEIF` բլոկները կարող են հանդիպել զրո
կամ ավելի անգամներ, իսկ `ELSE` բլոկը պարտադիր չէ։

Բոլոր `IF` և `ELSEIF` ճյուղերի պայմաններում արտահայտությունը
պետք է հաշվարկվի տրամաբանական արժեքի։ 

Նախապայմանով ցիկլն իր մարմնի հրամանները կատարում է այնքան 
ժամանակ, քանի դեռ `WHILE` բառից հետո գրված տրամաբանական
արտահայտությունը հաշվարկվում է _ճշմարիտ_ (`TRUE`) արժեքի։

```ebnf
While = 'WHILE' Expression Sequence 'END' 'WHILE'.
```

Հաշվիչով կամ պարամետրով ցիկլի `FOR` հրամանում պարամետրի 
սկզբնական ու վերջնական արժեքները, ինչպես նաև քայլը 
հաշվարկվում են մեկ անգամ, ցիկլի կատարումից առաջ։ Քայլի
լռելության արժեքը 1 է, իսկ 0-ն թույլատրված չէ։ Դրական 
քայլի դեպքում մարմինը կատարվում է, քանի դեռ պարամետրը 
`<=` սահմանին է, իսկ բացասական քայլի դեպքում՝ քանի դեռ 
պարամետրը `>=` սահմանին է։

```ebnf
For = 'FOR' IDENT '=' Expression 'TO' Expression [ 'STEP' ['+' | '-'] NUMBER ] Sequence 'END' 'FOR'.
```

Նշենք, որ `STEP`-ի համար թույլատրում ենք միայն դրական կամ բացասական հաստատուններ։

Ենթածրագրի կանչի `CALL` հրամանը կարող է մի քիչ հնաոճ ու արհեստական թվալ,
բայց այն ներմուծել ենք նաև հետագա պարզեցման նպատակով.

```ebnf
Call = 'CALL' IDENT [ ExpressionList ].
```

Արտահայտությունների ցուցակը կազմվում է ստորակետով իրարից 
անջատված արտահայտություններից։ 

```ebnf
ExpressionList = Expression { ',' Expression }.
```

Մինչև արտահայտությունների շարահյուսությունը սահմանելը թվարկենք 
բոլոր այն գործողությունները, որ կարող են օգտագործվել դրանց մեջ։
Ստորև գործողությունների աղյուսակն է՝ նախապատվությունների աճման
կարգով։

|Գործողություն         | Իմաստ           |
|:--------------------:|-----------------|
| `OR`                 | դիզյունքցիա     |
| `AND`                | կոնյունքցիա     |
| `NOT`                | ժխտում          |
| `=`, `<>`            | հավասարություն  |
| `>`, `>=`, `<`, `<=` | համեմատություն  |
| `+`, `-`, `&`        | ադիտիվ          |
| `*`, `/`, `\`, `MOD` | մուլտիպլիկատիվ  |
| `^`                  | աստիճան         |
| ունար `+`, `-`       | ունար           |
| `[]`                 | ինդեքս          |
| `f(...)`             | ֆունկցիայի կանչ |

1. `OR`, `AND`, `NOT` գործողությունների օպերանդները տրամաբանական են և արդյունքն էլ տրամաբանական է։ `AND`-ը և `OR`֊ը հաշվարկվում են կարճ
հաշվարկման սխեմայով։
2. `=`, `<>` գործողություններով կարող են համեմատվել ցանկացած պարզ տիպի երկու նույնատիպ արժեքներ, արդյունքը տրամաբանական է։
3. `>`, `>=`, `<`, `<=` գործողություններով կարող են համեմատվել երկու թվային կամ երկու տեքստային արժեքներ, արդյունքը տրամաբանական է։
4. `+`, `-` բինար գործողությունների օպերանդները թվային են, արդյունքը՝ թվային։ `&` գործողության օպերանդները տեքստային են, արդյունքը նույնպես տեքստային է։
5. `*`, `/`, `\`, `MOD` գործողությունների օպերանդները թվային են, արդյունքը՝ թվային։ `\` գործողությունը քանորդը վերադարձնում է որպես 0 կոտորակային մասով իրական թիվ, նույն կերպ `MOD` գործողության արդյունքը 0 կոտորակային մասով իրական թիվ է։
6. `^` գործողությունը, ի տարբերություն մյուս բինար գործողությունների, աջ-զուգորդական է, օպերանդները թվային են, արդյունքը թվային է։
7. Ունար `+`, `-` գործողությունները կիրառելի են միայն թվային օպերանդներին և տալիս են թվային արդյունք։
8. Զանգվածի տարրին դիմելու `[]` գործողությունը ձախ կողմում սպասում է զանգված, աջ կողմում՝ ամբողջ արժեք ունեցող թվային արտահայտություն, արդյունքը ձախ օպերանդի զանգվածի բազային տիպն է։
9. Ֆունկցիայի կիրառման արգումենտները կարող են լինել պարզ արժեքներ ու դրանց զանգվածներ՝ կանչվող ֆունկցիայի պարամետրերին համապատասխան։ Արդյունքը կարող է լինել միայն պարզ արժեք։ 

Հիմա այս ասվածը՝ շարահյուսական կանոններով․

```ebnf
Expression = Disjunction.
Disjunction = Conjunction { 'OR' Conjunction }.
Conjunction = Negation { 'AND' Negation }.
Negation = { 'NOT' } Equality.
Equality = Comparison [ ('=' | '<>') Comparison ].
Comparison = Addition [ ('>' | '>=' | '<' | '<=') Addition ].
Addition = Multiplication { ('+' | '-' | '&') Multiplication }.
Multiplication = Power { ('*' | '/' | '\' | 'MOD') Power }.
Power = Unary [ '^' Power ].
Unary = { ('+' | '-') } Subscript.
Subscript = Factor [ '[' Expression ']' ].
Factor = 'TRUE' | 'FALSE' | NUMBER | STRING
       | IDENT [ '(' [ ExpressionList ] ')' ]
       | '(' Expression ')'.
```

Եթե զանգվածը հայտարարվել է, օրինակ, հետևյալ կերպ․

```basic
DIM a[3] AS TEXT
```

Եվ ունենք ենթածրագիր-պրոցեդուրա, որի պարամետրը զանգված է, օրինակ․

```basic
SUB PrintTexts(x[] AS TEXT)
  ' արտածել տեքստերը
END SUB
```

Ապա `PrintTexts` պրոցեդուրայի կանչը կունենա `CALL PrintTexts a` 
տեսքը։ Իմաստային վերլուծիչը պարտավոր է համոզվել, որ կանչի արգումենտը 
համապատասխանում է ենթածրագրի պարամետրի տիպին։

## Բառակազմություն

Կեռաս լեզվում մեկնաբանությունները սկսվում են `'` նիշով 
ու շարունակվում են մինչև տողի վերջը։ Նոր տողին անցման 
նիշը մեկնաբանության մաս չէ։

Բոլոր ծառայողական բառերը, դրանք են `SUB`, `END`, `AS`, 
`BOOL`, `REAL`, `TEXT`, `DIM`, `LET`, `IF`, `THEN`, 
`ELSEIF`, `ELSE`, `WHILE`, `FOR`, `TO`, `STEP`, `CALL`, 
`TRUE`, `FALSE`, `OR`, `AND`, `NOT`, `MOD`, զգայուն են 
ռեգիստրի նկատմամբ և գրվում են մեծատառերով։

Իդենտիֆիկատորները որոշվում են `[A-Za-z_][A-Za-z0-9_]*` 
կանոնավոր արտահայտությամբ։ Դրանք նույնպես զգայուն են 
ռեգիստրի նկատմամբ․ `myau`, `Myau` և `MYAU` տարբեր 
անուններ են։

Թվային հաստատունները որոշվում են `[0-9]+(\.[0-9]+)?`
կանոնավոր արտահայտությամբ։ `-3.14`-ը ոչ թե բացասական
թիվ է, այլ արտահայտություն, որում ունար մինուսը 
կիրառված է `3.14` թվի նկատմամբ։

Տեքստային հաստատունները `"` չակերտների միջև վերցրած 
նիշերի հաջորդականություններ են. դրանց ներսում `"` 
և նոր տողի նիշ չեն թույլատրվում։ Escape֊ները նույնպես 
թույլատրված չեն։


## Իմաստաբանություն

### Մուտքի կետը

Ամեն մի Կեռաս ծրագիր պետք է ունենա ճիշտ մեկ `Main` անունով
ենթածրագիր։ Սա մուտքի կետն է, սրանից է սկսվում ծրագրի 
կատարումը։ `Main`-ը պարամետրեր չունի և արժեք չի վերադարձնում։

### I/O

Տվյալների ներմուծումն ու արտածումը կատարվում են ներդրված
ենթածրագրերով։ `Print`-ը արտածման ստանդարտ հոսքին է դուրս 
բերում իրեն տրված արտահայտության արժեքը։ Օրինակ.

```basic
CALL Print "Ok"
CALL Print 3.1415^2
```

`Input`-ը ենթածրագիր-ֆունկցիա է, որը վերադարձնում է ստանդարտ
ներմուծման հոսքից տրված տեքստը։ Օգտագործողի գործն է այն ձևափոխել
այլ տիպի։ Օրինակ.

```basic
DIM s AS TEXT
LET s = Input()
DIM n AS REAL
LET n = NUM(Input())
```

### Անունների եզակիություն

Բոլոր սահմանված ենթածրագրերի անունները գլոբալ տեսանելիության
տիրույթում են։ Գլոբալում փոփոխականներ կամ զանգվածներ չի
կարելի սահմանել։

Ենթածրագրի մարմինը ձևավորում է նոր տեսանելիության տիրույթ,
որտեղ հայտնվում են ենթածրագրերի պարամետրերը, `DIM`-ով
բացահայտ սահմանված անունները, `FOR`-ի անբացահայտ սահմանվող
հաշվիչը և ֆունկցիայից արժեք վերադարձնող փոփոխականը, որի
անունը համընկնում է ենթածրագիր ֆունկցիայի անունի հետ։
Ենթածրագրի մարմնում անունը երկու անգամ սահմանել չի կարելի։

### Սկզբնական արժեքները

`DIM`-ով սահմանված պարզ փոփոխականները ստանում են լռելության
արժեքներ ըստ իրենց տիպի։ `REAL`-ը՝ 0, `TEXT`-ը՝ դատարկ տող,
`BOOL`-ը՝ `FALSE`։ 

### `FOR`-ի պարամետրը

`FOR` հրամանի պարամետրը տեսանելի է ամբողջ ենթածրագի 
մարմնում։ Եթե `FOR`-ի կատարվելու պահին արդեն կա իր հաշվիչի
անունով նոր սահմանում, ապա օգտագործվում է հենց դա։ Հակառակ
դեպքում `FOR`-ը ներմուծում է նոր `REAL` փոփոխական։ Օրինակ.

```basic
DIM j AS REAL
' ....
FOR j = 1 TO 12 STEP 2
  ' ...
END FOR
```

Այստեղ `FOR`-ը նոր `j` չի սահմանում ու օգտագործում է արդեն
բացահայտ սահմանվածը։ Մի այլ դեպք.

```basic
' ուրիշ i սահմանված չէ
FOR i = 12 TO 2 STEP -2
  ' ...
END FOR
```

Այստեղ արդեն `FOR`-ը սահմանում է նոր `i` (համարժեք `DIM i AS REAL`)։

### Զանգվածի չափը

`DIM` հրամանում զանգվածի չափը որոշող արտահայտությունը պետք է հաշվարկվի 
դրական, ամբողջ արժեք ունեցող `REAL`-ի։ Ակնհայտորեն հետևյալ օրինակում
`r`-ը սահմանվում է որպես 6 տեքստերի զանգված։

```basic
DIM pi AS REAL
LET pi = 3.1415
DIM r[2 * pi] AS TEXT
```

### Պարամետրերի փոխանցումը

Պարզ տիպերով պարամետրերը փոխանցվում են արժեքով։ Զանգվածները
փոխանցվում են հղումով։ Ենթածրագիրը կարող է փոխել իրեն փոխանցված 
զանգվածը։
