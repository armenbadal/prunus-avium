# Կեռաս լեզուն

_Կեռասը_ Բեյսիկ լեզվի նմանությամբ ստեղծված շատ փոքր լեզու է՝ նախատեսված 
իմ գրքում ծրագրավորման լեզվի կոմպիլյատոր իրականացնելը նկարագրելու համար։ 
Ինչպես արդեն ներածությունում նշեցի, Կեռասը միտումնավոր է նախագծված նվազագույն
հնարավորություններով ու երբեմն էլ հնացած, ժամանակակից ծրագրավորման լեզուներին
չնմանվող բաղադրիչներով։ Այն ունի երեք պարզ տիպ, փոփոխականներ ու միաչափ 
զանգվածներ, ճյուղավորման և կրկնության հրամաններ, ֆունկցիաներ ու պրոցեդուրաներ։ 
Այսքանը բավական է ոչ միայն օգտակար փոքր ծրագրեր գրելու, այլև կոմպիլյատորի 
իրականացման գրեթե բոլոր հիմնական խնդիրներին հանդիպելու համար։

Հենց այս պահից ընթերցողին առաջարկում եմ լեզվի նախագծման ու իրականացման բոլոր 
թերությունները, անհարմարություններն ու սխալները համարել ինքնուրույն կատարելու
վարժություններ։ Այս մասին դեռ էլի կխոսեմ [Լեզվի ընդլայնման նախագծեր](ch09-projects.md)
գլխում։ 

Այս գլխում լիարժեք ու վերջնական կսահմանեմ Կեռաս լեզուն։ Կսահմանեմ ոչ միայն դրա
շարահյուսությունը, այլ նաև սեմանտիկան։ Իսկ հետագա գլուխներում, երբ անհրաժեշտ
կլինի իրականացման ինչ-որ որոշում կայացնել, հիմք կընդունեմ այս գլխում սահմանվածը։
Ուրեմն այս գլուխը մեր հետագա աշխատանքի հիմնական «պայմանագիրն» է. երբ  բառային 
վերլուծիչը պետք է որոշի, թե որտեղ է ավարտվում թիվը, շարահյուսական վերլուծիչը՝ ինչպես 
է կառուցված `IF` հրամանը, իսկ իմաստային վերլուծիչը՝ կարելի՞ է արդյոք թվին տեքստ 
վերագրել, պատասխանը պետք է փնտրել հենց այստեղ։


## Առաջին Կեռաս ծրագրերը

Ծրագրավորման լեզուներին ծանոթանալիս ավանդույթ է դարձել առաջինը գրել աշխարհքին
ողջունող ծրագիր։ Ահա այն Կեռաս լեզվով.

```cerasus
SUB Main
    CALL Print "Hello, world!"
END SUB
```

Սահմանված է `Main` անունով ենթածրագիրը, որի մարմնում `CALL` հրամանով
`Print` ենթածրագիրը կանչվում է `Hello, world!` տողի համար։

Համաձայնեք, որ այս երեք տողը ոչ մի իրական պատկերացում չեն տալիս լեզվի
հատկությունների մասին։ Բերենք մի ուրիշ օրինակ. ենթածրագիր, որը հաշվում է
տրված երկու վեկտորների սկալյար արտադրյալը.

```cerasus
SUB Scalar(u[] AS REAL, v[] AS REAL) AS REAL
    IF LEN(u) <> LEN(v) THEN
        RETURN 0
    END IF

    DIM result AS REAL
    FOR i = 0 TO LEN(a) - 1
        LET result = result + a[i] * b[i]
    END FOR

    RETURN result
END SUB
```

Այս օրինակն արդեն ավելի շատ բան է ասում լեզվի հնարավորությունների մասին։
Ենթածրագիրը սկսվում է `SUB` բառով և ավարտվում է `END SUB`-ով։ Փոփոխականը
սահմանվում է `DIM` հրամանով, արժեքը վերագրվում է `LET`-ով, պայմանական
կատարումը գրվում է `IF`-ով, իսկ `FOR` հրամանով կազմակերպվում է պարամետրով
կրկնություն։ Կեռասում հրամանն ավարտվում է տողի հետ։


## Բառակազմություն (լեքսիկա)

Կոմպիլյատորի մուտքին տրվող ծրագրի տեքստը պարզապես նիշերի հաջորդականություն 
է։ Այդ նիշերի հոսքից քերականական կառուցվածքներ ճանաչելու համար պետք է նախ
հոսքը տրոհել լեզվի բառային միավորների՝ լեքսեմների։ Կեռաս լեզվի բառային 
միավորներ են իդենտիֆիկատորները, ծառայողական բառերը, լիտերալները, 
գործողությունների նշաններն ու կետադրական նիշերը։ Տրոհման ընթացքում պետք
է դեն նետել բոլոր այն նիշերը, որոնք իմաստ չեն կրում և շարահյուսական
միավորներ կառուցելիս ավելորդ են։ Այդպիսիք են բացատանիշերն ու 
մեկնաբանությունները։

### Բացատանիշերն ու նոր տողը

Բացատանիշերից Կեռասին հետաքրքրում է միայն նոր տողին անցման նիշը, որը
ցույց է տալիս հրամանի ավարտ կամ հրամանների բլոկի սկիզբ։ Մյուս բոլոր 
բացատանիշերը պարզապես անտեսվում են։ Օրինակ, հետևյալ երեք տողերը, որ 
տարբերվում են միայն բացատների տեղով ու քանակով, ճիշտ նույն իմաստն
ունեն.

```cerasus
LET area = radius * radius
LET area=radius*radius
LET     area = radius     * radius
```

Քանի որ նոր տողին անցնելու `\n` նիշը լեզվում հատուկ իմաստ ունի, ուրեմն
թույլատրված չէ երկար տողերի տրոհումը՝ տողադարձումը։ Օրինակ, այսպես.

```cerasus
LET area = 3.1415926 *
    radius^2
```

> Ի դեպ, սա կարող է լինել առաջին վարժությունը. Կեռասում `_` նիշն ավելացնել
որպես տողերի տրոհման նիշ (կամ գործողություն)։


### Մեկնաբանությունները

Մեկնաբանությունը սկսվում է `'` նիշով և շարունակվում է մինչև տողի վերջը։ 
Նոր տողի նիշը մեկնաբանության մաս չէ։ Օրինակ.

```cerasus
' սա ամբողջ տողովը զբաղեցնող մեկնաբանություն է
LET radius = 5  ' սա էլ՝ տողը շարունակող մեկնաբանություն է
```

Կեռասում բազմատող մեկնաբանություններ չկան. ամեն նոր տողի սկզբում պետք է 
նորից գրել `'` նիշը։


### Ծառայողական բառերը

Կեռասի ծառայողական բառերն են. 
`SUB`, `END`, `AS`, `DIM`, `LET`, `IF`, `THEN`, `ELSEIF`, `ELSE`,
`WHILE`, `FOR`, `TO`, `STEP`, `CALL`, `RETURN`, `BOOL`, `REAL`,
`TEXT`, `TRUE`, `FALSE`, `OR`, `AND`, `NOT`, `MOD`, `TRUE`, `FALSE`:

Դրանք գրվում են միայն մեծատառերով և զգայուն են տառերի ռեգիստրի նկատմամբ։
Օրինակ, `IF`-ը ծառայողական բառ է, իսկ `If`-ը և `if`-ը՝ սովորական անուններ։


### Իդենտիֆիկատորները

Ենթածրագրերի, պարամետրերի, փոփոխականների ու զանգվածների անունները բառային
վերլուծիչի համար իդենտիֆիկատորներ են և այս գլխի շարահյուսական կանոններում 
հանդիմում են որպես `IDENT`։ Իդենտիֆիկատորը սկսվում է լատինական տառով և 
կարող է շարունակվել լատինական տառերով ու թվանշաններով.

```text
[A-Za-z][A-Za-z0-9]*
```

Օրինակ, `x`, `radius`, `Point2` և `IsPrime` թույլատրելի անուններ են, իսկ
`2nd`, `two_words` ու `շառավիղ` անունները՝ ոչ։ 

Անունները նույնպես զգայուն են ռեգիստրի նկատմամբ։ `radius`, `Radius` և
`RADIUS` երեք տարբեր անուններ են։ 


### Թվային լիտերալներ

Կեռասի թվային լիտերալները կամ հաստատունները գրվում են միայն տասական 
համակարդում և պետք համապատասխանեն հետևյալ կանոնավոր արտահայտությանը.

```text
[0-9]+(\.[0-9]+)?
```

Այս կանոնին համապատասխանում են `0`, `17`, `3.14` և `1981.06` թվերը։ 
Թվի ամբողջ մասը պարտադիր է, իսկ եթե գրված է կետը, ապա կոտորակային 
մասը նույնպես պարտադիր է։ Հետևաբար `.5` և `5.` գրառումները ճիշտ 
թվային լիտերալներ չեն։ 


### Տեքստային լիտերալներ

Տեքստային լիտերալը զույգ `"` չակերտների միջև վերցրած նիշերի 
հաջորդականություն է.

```cerasus
"Cerasus"
"Hello, world!"
""
```

Տեքստային լիտերալում նոր տող ու `"` գրել չի կարելի։


### Գործողություններ ու հատուկ նիշեր

Կեռաս լեզվում հետևյալ նիշերը կամ նիշերի զույգը օգտագործվում
են գործողությունների նշանակման համար.

```text
=   <>   <   <=   >   >=
+   -    *   /    \    ^    &
```

Հաուկ իմաստ ունեն կլոր ու ուղղանկյուն փակագծերն ու ստորակետը.

```text
(   )    [   ]    ,
```

Նկատենք, որ `=` նիշը երկու դեր ունի. `LET` և `FOR` հրամաններում 
այն կառուցվածքի բաժանիչ է, իսկ արտահայտության մեջ՝ հավասարության 
ստուգման գործողություն։ Նրա դերը որոշվում է համատեքստից։


## Բեկուսի—Նաուրի ընդլայնված նոթագրությունը

Լեզվի շարահյուսական կառուցվածքը նկարագրելու համար օգտագործել եմ Բեկուսի-Նաուրի
ընդլայնված նոթագրությունը։ Այդտեղ ամեն մի հավասարություն կամ կանոն `=` նիշով
բաժանված է ձախ ու աջ մասերի։ Ձախ կողմում նկարագրվող կառուցվածքի անունն է, իսկ 
աջ կողմում՝ նրա հնարավոր տեսքերը։ Օրինակ.

```ebnf
TypeName = 'REAl' | 'TEXT' | 'BOOL'.
```

Ուղղաձիգ գիծը նշանակում է «կամ», հետևաբար `TypeName`-ը կարող է լինել `BOOL`, 
`REAL` կամ `TEXT` տարբերակներից որևէ մեկը։ Ապաթարցերի մեջ վերցրած բառերն ու 
նիշերը ծրագրում պետք է հանդիպեն հենց այդ տեսքով։ Մեծատառերով, բայց առանց 
ապաթարցերի գրված `IDENT`, `NUMBER`, `STRING`, `NEWLINE` և `EOF` անունները 
առանձին սահմանվող կամ նախապես որոշված բառային (լեքսիկական) տարրեր են։

EBNF-ի մյուս պայմանական նշաններն են.

| Գրառում  | Իմաստ |
|:--------:|:------|
| `[ X ]`  | `X`-ը կարող է լինել կամ չլինել |
| `{ X }`  | `X`-ը կարող է կրկնվել զրո կամ ավելի անգամ |
| `( X )`  | `X`-ը դիտարկվում է որպես մեկ խումբ |
| `X Y`    | `X`-ին անմիջապես հաջորդում է `Y`-ը |
| `X \| Y` | գրվում է կամ `X`-ը, կամ `Y`-ը |

Մի ուրիշ օրինակ՝

```ebnf
NewLines = NEWLINE { NEWLINE }.
```

Այստեղ `NewLines` ոչ-տերմինալային սիմվոլը սահմանվել է որպես նոր տողին 
անցնելու մեկ կամ ավելի նիշ։ 


## Ծրագիրը

Կեռաս ծրագիրը մեկ տեքստային ֆայլում գրված ենթածրագրերի հաջորդականություն 
է։ Այսպես.

```ebnf
Program = [ NewLines ] { Subroutine NewLines } EOF.
NewLines = NEWLINE { NEWLINE }.
```

Ըստ այս կանոնի ծրագրի սկզբում թույլատրվում են դատարկ տողեր։ Դրանցից 
հետո սահմանվում են զրո կամ ավելի ենթածրագրեր, իսկ վերջում պետք է 
լինի ֆայլի ավարի նիշը՝ `EOF`-ը։ Ձևականորեն քերականությունը թույլ է 
տալիս նաև ոչ մի ենթածրագիր չպարունակող դատարկ ֆայլ, բայց այդպիսի 
ծրագիրը կատարել հնարավոր չէ։ Իմաստային կանոնները պահանջում են, որ
ամեն մի ծրագրում լինի ճիշտ մեկ `Main` անունով ենթածրագիր։

Բոլոր ենթածրագրերը գրվում են իրար հաջորդելով և ամբողջ ծրագրում 
տեսանելի են։ Ուրեմն ենթածրագիրը կարելի է օգտագործել սահմանումից առաջ, 
ինչպես նաև կարելի է գրել ռեկուրսիվ ֆունկցիա, որն ուղղակի կամ այլ 
ֆունկցիայի միջոցով կանչում է ինքն իրեն։


## Ծրագրի մուտքի կետը

Ամեն Կեռաս ծրագիր պետք է ունենա ճիշտ մեկ `Main` անունով ենթածրագիր։ 
Ծրագրի կատարումը սկսվում է դրանից։ `Main`-ը պետք է պրոցեդուրա լինի՝ 
առանց պարամետրերի և վերադարձվող տիպի.

```cerasus
SUB Main
    ' ծրագրի կատարումը սկսվում է այստեղից
END SUB
```

Հետևյալ երկու վերնագրերն իմաստային սխալներ են.

```cerasus
SUB Main(value AS REAL)  ' Main-ը պարամետր չի կարող ունենալ
END SUB

SUB Main AS REAL         ' Main-ը արժեք չի կարող վերադարձնել
    RETURN 0
END SUB
```


## Ենթածրագիրը

Կեռաս ծրագրի հիմնական կառուցվածքային միավորը ենթածրագիրն է։ Այն կարող 
է լինել կամ _պրոցեդուրա_, որը որևէ գործողություն է կատարում և կողմնակի
էֆեկտ է թողնում, կամ _ֆունկցիա_, որը նաև արժեք է վերադարձնում։ Երկուսն 
էլ սկսվում են `SUB` բառով ու ավարտվում `END SUB` բառերով.

Շարահյուսական կանոնը ցույց է տալիս, որ ենթածրագիր սահմանելու համար
անպայման պետք է նշել միայն անունը, իսկ պարամետրերի ցուցակն ու 
վերադարձվող արժեքի տիպը պարտադիր չեն։

```ebnf
Subroutine = 'SUB' IDENT [ '(' [ ParameterList ] ')' ] [ 'AS' TypeName ]
             Sequence 'END' 'SUB'.
```

Ամենապարզ պրոցեդուրան կարող է այսպիսի տեսք ունենալ.

```cerasus
SUB Dummy
END SUB
```

Պարամետրեր չունեցող ենթածրագրի սահմանման մեջ դատարկ փակագծերը կարելի 
է և՛ գրել, և՛ բաց թողնել։ `SUB SayHello()` և `SUB SayHello` վերնագրերը 
համարժեք են։

Պարամետրերը գրվում են փակագծերի մեջ՝ ստորակետերով բաժանված։ Այդ ցուակում
ամեն մի անունի հետ պարտադիր պետք է նշված լինի նաև տիպը։

```ebnf
ParameterList = Parameter { ',' Parameter }.
Parameter = IDENT [ '[' ']' ] 'AS' TypeName.
```

Օրինակ, հետևյալ ենթածրագիրը տպում է իրեն տրված երկու իրական արժեքներից
ավելի մեծը.

```cerasus
SUB PrintMaximum(x AS REAL, y AS REAL)
    IF x > y THEN
        CALL Print x
    ELSE
        CALL Print y
    END IF
END SUB
```

Ասացի, որ ամեն մի պարամետր ունի անուն և տիպ։ Պարզ պարամետրերը ենթածրագրին 
փոխանցվում են որպես արժեք. ենթածրագրի մարմնում դրա արժեքի փոփոխությունը
կանչողի կողմում տեսանելի չէ։ 

Եթե պարամետրը զանգված է, ապա պետք է նրա անունից հետո գրել մի զույգ 
ուղղանկյուն փակագծեր. `[]`։ Օրինակ, հետևյալ `Clear` պրոցեդուրան
զրոյացնում է իրեն տրված զանգվածի բոլոր տարրերը։

```cerasus
SUB Clear(values[] AS REAL)
    FOR index = 0 TO LEN(values) - 1
        LET values[index] = 0
    END FOR
END SUB
```

Քանի որ զանգվածը փոխանցվում է որպես հղում, `Clear`-ի կատարած 
փոփոխությունները կատարվում են կոնչողի տված նմուշի վրա։

Եթե ենթածրագրի վերնագիրն ավարտվում է տիպի նշումով, ապա դա 
ֆունկցիա է և կարող `RETURN` հրամանով արժեք վերադարձնել։

```cerasus
SUB Maximum(x AS REAL, y AS REAL) AS REAL
    IF x > y THEN
        RETURN x
    ELSE
        RETURN y
    END IF
END SUB
```

Ֆունկցիան կարող է վերադարձնել միայն պարզ `BOOL`, `REAL` կամ `TEXT` 
արժեք։

Ենթածրագրի մարմինը առանձին լոկալ անունների տիրույթ է։ Այս տիրույթում
են վավեր պարամետրերը, `DIM` հրամանով բացահայտ սահմանված անուններն ու 
`FOR` հրամանի պարամետրերը։ Արգելվում է ենթածրագրի մարմնում նույն 
անունը մեկից ավելի անգամ սահմանել։ Օրինակ, հետևյալ կոդում `IF`
հրամանի մարմնում սահմանված երկրորդ `value`-ն թույլատրված չէ։

```cerasus
SUB Main
    DIM value AS REAL
    IF TRUE THEN
        DIM value AS TEXT
    END IF
END SUB
```

## Տիպերն ու արժեքները

Քանի որ խոսք գնաց ենթածրագրի պարամետրերի ու վերադարձրած արժեքի 
տիպերի մասին, այստեղ քննարկենք Կեռաս լեզվի տիպերի համակարգն ու
դրանց համապատասխան արժեքների բազմությունները։ Հետո կվերադառնանք
հրամանների ու արտահայտությունների շարահյուսությունն ու սեմանտիկան 
նկարագրելուն։

Կեռասը _ստատիկ տիպավորմամբ_ լեզու է։ Ամեն փոփոխականի, պարամետրի 
և արտահայտության տիպը որոշվում է մինչև ծրագրի կատարումը։ Եթե, 
օրինակ, `radius` փոփոխականը հայտարարվել է որպես իրական թիվ, ապա 
նրան տեքստ վերագրել չի կարելի։

Լեզվի պարզ տիպերը երեքն են. տրամաբանակն, իրական թվային և տեքստային։

```ebnf
TypeName = 'BOOL' | 'REAL' | 'TEXT'.
```

Տրամաբանական տիպի արտահայտությունները կարող են ընդունել միայն 
`TRUE` և `FALSE` արժեքներ։ Այդպիսի արտահայտություններն օգտագործվում 
են  հիմնականում պայմանների և տրամաբանական գործողությունների համար։ 
`REAL`-ը Կեռասի միակ թվային տիպն է։ Անունից երևում է, որ դա իրական
թիվն է։ Տեքստային տիպի արժեքները ստատիկ սահմանված ու դինամիկ 
կառուցված տողերն են։

Կեռասը տիպերի անբացահայտ ձևափոխություններ չի կատարում, այսինքն՝ 
այն _տիպերի խիստ ստուգումով_ լեզու է։ `TRUE`-ն թիվ չէ, `0`-ն՝ 
տրամաբանական արժեք, իսկ `"17"`-ը՝ թիվ։ Եթե ներմուծված `"17"` տեքստը
պետք է օգտագործել որպես թիվ, այն բացահայտ ձևով պետք է փոխակերպել `NUM`
ներդրված ֆունկցիայով։ Նույն խստությունն է գործում վերագրումների, 
գործողությունների, ենթածրագրերի արգումենտների և վերադարձվող արժեքների 
համար։

Պարզ տիպով փոփոխականներից բացի կեռասը հնարավորություն է տալիս սահմանել 
նաև դրան միաչափ զանգվածներ։ Զանգվածը բաղադրյալ արժեք է։ Այն չի կարելի 
ամբողջությամբ վերագրել, վերադարձնել ֆունկցիայից կամ տալ պարզ արժեք 
սպասող գործողությանը։ 


## Հրամանների հաջորդականություն

Կեռաս լեզվում հրամանները կամ ղեկավարող կառուցվածքները յոթն են։
Փոփոխական հայտարարող `DIM`-ը, արժեք վերագրող `LET`-ը, ճյուղավորման 
`IF`-ը, նախապայմանով `WHILE` ցիկլը, հաշվիչով `FOR` ցիկլը, 
պրոցեդուրայի կանչի `CALL`-ը և ֆունկցիայից արժեք վերադարձնող 
`RETURN`-ը։

```ebnf
Statement = Dim | Let | If | While | For | Call | Return.
```

Շարահյուսական կանոններում հրամանների հաջորդականությունը կամ բլոկը 
կնշանակենք `Sequence` սահմանմամբ.

```ebnf
Sequence = NewLines { Statement NewLines }.
```

Սա ասում է, որ բլոկը պարտադիր սկսվում է նոր տողով։ Ապա ամեն հրամանից 
հետո նույնպես պետք է լինի գոնե մեկ նոր տող։ 


## Փոփոխականի ու զանգվածի սահմանում

Փոփոխականը կամ զանգվածը սահմանվում է `DIM` հրամանով.

```ebnf
Dim = 'DIM' IDENT [ '[' Expression ']' ] 'AS' TypeName.
```

Պարզ փոփոխականի համար գրվում են նրա անունն ու տիպը.

```cerasus
DIM radius AS REAL
DIM message AS TEXT
DIM ready AS BOOL
```

Այս հայտարարություններից հետո `radius`-ի արժեքը `0` է, `message`-ինը՝ 
դատարկ տող, իսկ `ready`-ինը՝ `FALSE`։ 

Եթե անունից հետո ուղղանկյուն փակագծերում տրված է չափը, սահմանվում է 
նշված տիպով միաչափ զանգված.

```cerasus
DIM values[100] AS REAL
DIM words[2 * count] AS TEXT
DIM flags[limit + 1] AS BOOL
```

Չափը կարող է լինել հաստատուն կամ կատարման ժամանակ հաշվարկվող արտահայտություն։
Այն պետք է հաշվարկվի դրական արժեք ունեցող `REAL` թիվ, որի ամբողջ մասը
օգտագորվում է որպես զանգվածի տարրերի քանակ։ 

Զանգվածի տարրերը համարակալվում են զրոյից։ Եթե զանգվածի տարրերի քանակը `n` 
է, թույլատրելի ինդեքսներն են `0`-ից մինչև `n - 1`։ 


## Վերագրում

Պարզ փոփոխական կամ զանգվածի տարրին նոր արժեք է վերագրվում `LET` հրամանով։

```ebnf
Let = 'LET' IDENT [ '[' Expression ']' ] '=' Expression.
```

Օրինակ.

```cerasus
LET radius = 5
LET area = 3.1415926 * radius^2
LET ready = area > 0
LET words[index] = "Cerasus"
```

Հավասարության ձախ կողմի անունը պետք է նախապես սահմանված լինի։ Եթե ինդեքս 
է օգտագործված, ապա վերագրվողը պետք է սահմանված լինի որպես զանգված։ `=` 
նշանի աջ կողմի արտահայտության տիպը պետք է ճիշտ նույնը լինի, ինչ դրա ձախ 
կողմում ստացված տիպը։

```cerasus
DIM radius AS REAL
LET radius = TRUE  ' ՍԽԱԼ. BOOL արժեքը չի կարելի վերագրել REAL-ին
```

Այս վերջին հրամանը քերականորեն ճիշտ է։ Այն ունի `LET` բառը, անունը,
հավասարության նշանն ու ճիշտ կառուցված արտահայտությունը։ Սխալը պարզվում 
է միայն անունը նրա հայտարարության հետ կապելուց ու երկու կողմերի տիպերը 
համեմատելուց հետո։


## Ճյուղավորում

Ծրագրի կատարման հոսքը որևէ պայմանով ճյուղավորելու համար սահմանված է 
արդեն սովորական դարձած `IF` հրամանը։ Լրիվ շարահյուսական կանոնն է.

```ebnf
If = 'IF' Expression 'THEN' Sequence
     { 'ELSEIF' Expression 'THEN' Sequence }
     [ 'ELSE' Sequence ]
     'END' 'IF'.
```

Սա ասում է, որ այլընտրանքների `ELSEIF` բլոկները կարող են կրկնվել, 
բնականաբար, տարբեր պայմաններով, իսկ `ELSE` բլոկը, եթե դրա 
անհրաժեշտությունը չկա, կարող է բացակայել։

`IF`-ի և `ELSEIF`-երի համար թույլատրելի են միայն `BOOL` արժեքի հաշվարկվող
արտահայտություններ։ 

Ամենակարճ տարբերակը, երբ կա միայն մեկ պայման ու մեկ որոշում.

```cerasus
IF temperature < 0 THEN
    CALL Print "It is cold."
END IF
```

Երկու այլընտրանք ընտրելու համար ավելացվում է `ELSE` ճյուղը.

```cerasus
IF number MOD 2 = 0 THEN
    CALL Print "even"
ELSE
    CALL Print "odd"
END IF
```

Իսկ մի քանի պայման հերթով ստուգելու համար կարելի է գրել ցանկացած քանակով
`ELSEIF` ճյուղեր.

```cerasus
IF value < 0 THEN
    LET sign = -1
ELSEIF value > 0 THEN
    LET sign = 1
ELSE
    LET sign = 0
END IF
```

Պայմանները հաշվվում են վերևից ներքև։ Կատարվում է առաջին ճշմարիտ պայմանին
համապատասխան մարմինը, իսկ հաջորդ ճյուղերն այլևս չեն դիտարկվում։ Եթե ոչ մի
պայման ճշմարիտ չէ, կատարվում է `ELSE` մարմինը, եթե այն կա։

`IF`, `ELSEIF` և `ELSE` բլոկների մարմինները նոր անունների տիրույթ չեն 
ստեղծում։ Դրանց ներսում գրված `DIM` հրամանով սահմանված անուններ տեսանելի 
են դառնում ամբողջ ենթածրագրին։


## Նախապայմանով ցիկլ

Երբ որևէ հրամանների խումբ պետք է կրկնել այնքան ժամանակ, քանի դեռ 
ճշմարիտ է տրված պայմանը, օգտագործվում է `WHILE` ցիկլը.

```ebnf
While = 'WHILE' Expression Sequence 'END' 'WHILE'.
```

Օրինակ, երկու դրական թվերի ամենամեծ ընդհանուր բաժանարարը կարելի 
է հաշվել այսպես.

```cerasus
WHILE x <> y
    IF x > y THEN
        LET x = x - y
    ELSE
        LET y = y - x
    END IF
END WHILE
```

Ամեն իտերացիայից առաջ հաշվվում է `WHILE`-ի պայմանը։ Այն պետք է 
հաշվարկվի տրամաբանական արժեքի։ Եթե արդյունքը ճշմարիտ է, կատարվում 
է մարմինը, հակառակ դեպքում ցիկլն ավարտվում է։ Եթե հենց առաջին իսկ 
ստուգման ժամանակ պայմանը կեղծ է, մարմինը ոչ մի անգամ չի կատարվի։


## Պարամետրով ցիկլ

`FOR` հնրաման օգտագործվում է հաշվիչով կամ պարամետրով ցիկլեր 
կազմակերպելու համար։ 

```ebnf
For = 'FOR' IDENT '=' Expression 'TO' Expression 
        [ 'STEP' [ '+' | '-' ] NUMBER ]
      Sequence 'END' 'FOR'.
```

Պետք է նշել պարամետրի սկզբնական արժեքը, նպատակային արժեքը և քայլը։
Վերջինս պարտադիր չէ ու լռելությամբ սահմանվում է `1`։

Օրինակ, եթե ծրագրում ինչ որ մի տեղ ունենք 10 տարրերի զանգված.

```cerasus
DIM values[10] AS REAL
```

ապա դրա ամեն մի տարրին իր ինդեքսի քառակուսին վերագրելու համար 
կարող ենք գրել այսմիսի մի հրաման.

```cerasus
FOR index = 0 TO LEN(values)-1
    LET values[index] = index^2
END FOR
```

Այստեղ `index` հաշվիչը սկզբում ստանում է `0`, իսկ ամեն իտերացիայից հետո
ավելանում է մեկով, քանի դեռ չի հավասարվել `LEN(values)-1` արժեքին։

Այդ նույն զանգվածի տարրերը հակառակ հաջորդականությամբ տպելու համար 
պետք է տալ բացասական քայլ.

```cerasus
FOR index = LEN(values)-1 TO 0 STEP -1
    CALL Print values[index]
END FOR
```

Սկզբնական ու վերջնական արժեքները որոշող արտահայտությունները պետք է 
հաշվարկվեն `REAL` արժեքների։ `STEP`-ից հետո կարելի է գրել միայն դրական 
կամ բացասական թվային հաստատուն։ Զրոյական քայլն արգելված է, որովհետև 
այդպիսի ցիկլը բնական ճանապարհով առաջ չի շարժվի։

Եթե ցիկլի պարամետրի անունով փոփոխական դեռ չկա, `FOR`-ն ինքն է ներմուծում 
նոր `REAL` տիպի փոփոխական։ Այդ անբացահայտ հայտարարությունը համարժեք է 
ենթածրագրում `DIM index AS REAL` գրելուն, իսկ անունը տեսանելի է ամբողջ 
ենթածրագրի մարմնում։ Եթե նույն անունով արդեն կա `TEXT`, `BOOL` կամ 
զանգվածային փոփոխական, ապա այն որպես `FOR`-ի հաշվիչ օգտագործել չի կարելի։


## Պրոցեդուրայի կանչ

Ի տարբերություն ժամանակակից ծրագրավորման լեզուների Կեռասում հատուկ 
հրաման է նախատեսված պրոցեդուրան կանչելու համար։ Դա `CALL` հրամանն է.

```ebnf
Call = 'CALL' IDENT [ ExpressionList ].
```

Արգումենտները գրվում են անունից հետո, առանց ընդգրկող փակագծերի.

```cerasus
CALL SayHello
CALL PrintMaximum 7, 12
CALL Clear values, count
```

Արգումենտների ցուցակը կարող է դատարկ լինել։ Հակառակ դեպքում արգումենտներն
իրարից բաժանվում են ստորակետերով։ Դրանց քանակը, հերթականությունը, տիպերն ու
պարզ կամ զանգվածային լինելը պետք է համապատասխանեն պարամետրերի ցուցակին։

`CALL`-ով կարելի է կանչել միայն արժեք չվերադարձնող ենթածրագիր՝ պրոցեդուրա։ 


## Ֆունկցիայից արժեքի վերադարձ

Ենթածրագիր-ֆունկցիայից արժեք վերադարձնելու համար է `RETURN` հրամանը.

```ebnf
Return = 'RETURN' Expression.
```

Արտահայտությունը պետք է հաշվարկվի պարզ արժեքի և համապատասխանի ֆունկցիայի 
վերնագրում հայտարարված տիպին։ `RETURN`-ը հաշվարկում է այդ արժեքը և անմիջապես 
ավարտում ֆունկցիայի կատարումը։

```cerasus
SUB IsPositive(value AS REAL) AS BOOL
    RETURN value > 0
END SUB
```

Պրոցեդուրայում `RETURN` գրել չի կարելի, որովհետև Կեռասի `RETURN` հրամանը միշտ
արժեք է պահանջում։ 

Ֆունկցիայի կատարման բոլոր հնարավոր ուղիները պետք է հասնեն `RETURN` հրամանի։
Հետևյալ ֆունկցիան սխալ է.

```cerasus
SUB Sign(value AS REAL) AS REAL
    IF value < 0 THEN
        RETURN -1
    END IF
END SUB
```

Երբ `value`-ը բացասական չէ, ֆունկցիան ավարտվում է առանց արժեքի։ Ճիշտ
տարբերակում պետք է ծածկել նաև մնացած ուղիները.

```cerasus
SUB Sign(value AS REAL) AS REAL
    IF value < 0 THEN
        RETURN -1
    ELSEIF value > 0 THEN
        RETURN 1
    ELSE
        RETURN 0
    END IF
END SUB
```

Ցիկլի ներսում գրված `RETURN`-ը միայնակ չի երաշխավորում արժեքի վերադարձը,
որովհետև ցիկլի մարմինը կարող է ոչ մի անգամ չկատարվել։ Իսկ բոլոր ճյուղերում
արժեք վերադարձնող և պարտադիր `ELSE` ունեցող `IF` հրամանը այդ երաշխիքը տալիս
է։ ??

## Արտահայտություններ

Կեռաս լեզվի արտահայտությունները կազմվում են հաստատուններից, փոփոխականներից, 
միտեղանի ու երկտեղանի գործողություններից, ինդեքսավորման գործողությունից, 
ֆունկցիայի կանչից։

Արտահայտությունների՝ մեզ համար սովորական դարձած գրառումն ապահովելու համար
շարահյուսական կանոններով մոդելավորվել են գործողությունների նախապատվությունն 
ու զուգորդությունն։ Հետևյալ աղյուսակում, որտեղ Կեռաս լեզվի գործողությունները
թվարկված են ըստ իրենց նախապատվությունների աճի, սահմանված են նաև դրանց 
օպերանդների ու արդյունքների տիպերը։

| Գործողություններ | Օպերանդները | Արդյունքը |
|:-----------------|:--------------------|:----------|
| `OR` | `BOOL`, `BOOL` | `BOOL` |
| `AND` | `BOOL`, `BOOL` | `BOOL` |
| `NOT` | `BOOL` | `BOOL` |
| `=`, `<>` | նույն պարզ տիպի երկու արժեք | `BOOL` |
| `>`, `>=`, `<`, `<=` | երկու `REAL` կամ երկու `TEXT` | `BOOL` |
| `+`, `-` | `REAL`, `REAL` | `REAL` |
| `&` | `TEXT`, `TEXT` | `TEXT` |
| `*`, `/`, `\`, `MOD` | `REAL`, `REAL` | `REAL` |
| `^` | `REAL`, `REAL` | `REAL` |
| միտեղանի `+`, `-` | `REAL` | `REAL` |
| `a[i]` | զանգված և `REAL` ինդեքս | տարրի պարզ տիպը |
| `f(...)` | ըստ ֆունկցիայի պարամետրերի | ֆունկցիայի պարզ տիպը |

Ամենացածր նախապատվությունն ունի տրամաբանական դիզյունքցիայի գործողությունը,
իսկ ամենաբարձրը՝ ֆունկցիայի կանչը։ Բոլոր երկտեղանի գործողությունները, բացի
աստիճան բարձրացնելու `^` գործողությունից, ձախ-զուգորդական են, իսկ `^`-ը՝
աջ զուգորդական է։ Համեմատման գործողությունները, բնականաբար, զուգորդելի չեն։

Շարահյուսական կանոններն էլ, ինչպես ցույց կտամ ստորև, սահմանված են ըստ 
այս աղյուսակի։


### Տրամաբանական գործողություններ

Դրանք երեքն են. `OR`, `AND`, `NOT`: `NOT`-ը ժխտում է մեկ տրամաբանական արժեք։ 
`AND`-ը ճշմարիտ է միայն այն դեպքում, երբ երկու օպերանդներն էլ ճշմարիտ են, իսկ 
`OR`-ը՝ երբ դրանցից գոնե մեկը ճշմարիտ է։

`AND` և `OR` գործողությունները հաշվարկվում են _կարճ հաշվարկման սխեմայով_։ Եթե
`AND`-ի ձախ օպերանդը `FALSE` է, ամբողջ արտահայտությունն արդեն կեղծ է, և աջ
օպերանդը չի հաշվարկվում։ Նույն կերպ, եթե `OR`-ի ձախ օպերանդը `TRUE` է, աջն
այլևս հաշվելու կարիք չկա։ 

Քանի որ `NOT`-ի նախապատվությունը համեմատման գործողություններից ցածր է, 
`NOT x = 0` գրառումը մեկնաբանվում է որպես `NOT (x = 0)`։ 

Դե, քանի որ `OR`-ն ունի ամենացածրա նախապատվությունը, `Expression`-ը 
սահմանեմ որպես `Disjunction`: Դիզյունքցիան՝ որպես կոնյունքցիաների շղթա,
կոնյունքցիան՝ որպես ժխտումների շղթա, իսկ ժխտումն էլ՝ որպես հավասարության
(`=`, `<>`) ժխտում։

```ebnf
Expression  = Disjunction.
Disjunction = Conjunction { 'OR' Conjunction }.
Conjunction = Negation { 'AND' Negation }.
Negation    = { 'NOT' } Equality.
```

Ուշադրություն դարձրեք, որ `Negation`-ի կանոնը հնարավորություն է տալիս 
գրել, օրինակ,

```cerasus
NOT NOT NOT NOT k = 8
```

### Հավասարությունն ու համեմատում

Հավասարության ու համեմատման գործողությունների համար երկու շարահյուսական
կանոն եմ նախատեսել։

```ebnf
Equality   = Comparison [ ('=' | '<>') Comparison ].
Comparison = Addition [ ('>' | '>=' | '<' | '<=') Addition ].
```

Այս տրոհումը հնարավորություն է տալիս `(a > 2) = (c <= 4)` արտահայտությունը
գրել առանց փակագծերի. `a > 2 = c <= 4`։

`=` գործողությունը ստուգում է երկու արժեքների հավասարությունը, իսկ `<>`-ը՝
անհավասարությունը։ Դրանց օպերանդները պետք է լինեն նույն պարզ տիպի, զանգվածների
հավասարություն կամ անհավասարություն ստուգել հնարավոր չէ։

`>`, `>=`, `<` և `<=` գործողությունները համեմատում են երկու թիվ կամ երկու տեքստ։
Տրամաբանական արժեքների համար փոքր կամ մեծ հարաբերություն սահմանված չէ։

Քանի որ համեմատման գործողությունները զուգորդելի չեն, Կեռաս լեզվում հնարավոր չէ
գրել `0 < x < 10` տեսքի հարաբերությունների շղթաներ։ Դրա փոխարեն պետք է գրել.

```cerasus
(0 < x) AND (x < 10)
```

### Թվաբանական գործողություններ

Թվաբանական գործողությունները բաժանված են երեք խմբի։ Առաջինում խմբում ադիտիվներն 
են՝ `+`, `-`, այստեղ է նաև տեքստերի կցման `&` գործողությունը, բայց սրա մասին՝ 
ստորև։ Երկրորդ խմբում մուլտիպլիկատիվներն են. `*`, `/`, `\\`, `MOD`: Իսկ
երրորդ խմբում միայն աստիճան բարձրացնելու `^` գործողությունն է։

```ebnf
Addition       = Multiplication { ('+' | '-' | '&') Multiplication }.
Multiplication = Power { ('*' | '/' | '\' | 'MOD') Power }.
Power          = Unary [ '^' Power ].
```

`\` գործողությունը վերադարձնում է բաժանման քանորդը որպես իրական թիվ։ Քանի որ
Կեռասն առանձին ամբողջաթիվ տիպ չունի, արդյունքը ներկայացվում է որպես `REAL` է։
Նմանապես `MOD`-ը վերադարձնում է բաժանման մնացորդը։ Օրինակ, `17 \ 5`-ի արժեքը 
`3.0` է, իսկ `17 MOD 5`-ինը՝ `2.0`։

`^` գործողությունն աջ-զուգորդական է։ Այսինքն՝ `2^3^2` գրառումը նշանակում է
`2^(3^2)`, այլ ոչ թե `(2^3)^2`։ 

Վերը հիշատակված `&` գործողությունը, որը երկու տեքստեր կցում է իրար ու վերադարձնում
է նոր տեքստ, իր բնույթով ադիտիվ է, ու դրա համար էլ այն թողել եմ թվաբանական ադիտիվների 
խմբում։

Թվաբանական միտեղանի գործողությունները երկուսն են. `+` և ՝-՝:

```ebnf
Unary = { ('+' | '-') } Subscript.
```

Տրամաբանական ժխտման գործողության պես սրանք էլ կարելի է կիրառել մեկը մյուսի նկատմամբ
Օրինակ.

```cerasus
+ - - + 45
```

Ակնհայտորեն, բոլոր միտեղանի գործողությունները աջ-զուգորդելի են։

### Ինդեքսավորում

Զանգվածի տարրին դիմելու գործողությունը թեև գրվածքով տարբեր է, բայց բնույթով շատ
նման է երկտեղանի գործողության։ Դրա ձախ կողմում զանգված է, իսկ ուղղանկյուն 
փակագծերում՝ թվային արժեքի հաշվարկվող արտահայտություն։ Արդյունքի տիպը զանգվածի 
տարրերի տիպն է։

```ebnf
Subscript      = Factor [ '[' Expression ']' ].
```

### Ֆունկցիայի կիրառում

Արտահայտության մեջ ֆունկցիան կիրառելիս նրա անունից հետո կլոր փակագծերում
պետք է գրել կիրառման արգումենտները՝ ստորակետով բաժանված։ Այսպես.

```cerasus
Input()       ' արգումենտ չկա
SQR(2)        ' մեկ արգումենտ
Maximum(x, y) ' երկու արգումենտ
```

Նույնիսկ արգումենտ չունեցող ֆունկցիայի դեպքում `()` փակագծերը պարտադիր են։
Դրանցով ֆունկցիայի կիրառությունը տարբերվում է նույնանուն փոփոխականից։
Արգումենտների քանակը, հերթականությունը, պարզ կամ զանգվածային լինելն ու տիպերը
պետք է համապատասխանեն ֆունկցիայի սահմանման պարամետրերին։ Արտահայտության 
արդյունքը ֆունկցիայի սահմանման ժամանակ որոշված վերադարձվող պարզ տիպն է։


## Ճիշտ և սխալ ծրագրերը

Մինչև հիմա մի քանի անգամ հանդիպեցինք «բառային», «շարահյուսական» և
«իմաստային» բնորոշումներին։ Ժամանակն է դրանք հստակ իրարից տարբերել։

_Բառային սխալի_ դեպքում ծրագրի տեքստում հանդիպող հերթական նիշերի շարքը 
հնարավոր չէ վերածել Կեռասի ճիշտ բառային միավորի։ Օրինակ.

```cerasus
LET value = 3.
```

Մեր թվային հաստատունի կանոնով կետից հետո գոնե մեկ թվանշան է պահանջվում։ Նույն
տիպի սխալ է առանց փակող չակերտի տեքստը կամ ծրագրի տեքստում հանդիպող լեզվին 
անհայտ `@` նիշը։ Այս սխալները հայտնաբերվում ու դրանց մասին ազդարարվում են 
բառային վերլուծիչի կողմից։

_Շարահյուսական սխալի_ դեպքում բոլոր առանձին բառային տարրերը ճիշտ են, բայց
դրանց հերթագայումը հնարավոր չէ համապատասխանեցնել որևէ ծարահյուսական կանոնի։
Օրինակ.

```cerasus
IF value > 0
    CALL Print value
END IF
```

Այստեղ `IF`-ի պայմանից հետո բացակայում է պարտադիր `THEN` բառը։ Այսպիսի
սխալները հայտնաբերվում ու ազդարարվում են շարահյուսական վերլուծիչի կողմից։

_Իմաստային սխալի_ դեպքում տեքստը ճիշտ բառերից կազմված և քերականորեն ճիշտ
ծրագիր է, բայց խախտում է անունների կամ տիպերի կանոնները։ Օրինակ.

```cerasus
SUB Main
    DIM value AS REAL
    LET value = FALSE
END SUB
```

Շարահյուսական վերլուծիչն առանց սխալի ծառ կկառուցի։ Միայն իմաստային վերլուծիչը
կպարզի, որ `REAL` փոփոխականին փորձ է արվում `BOOL` արժեք վերագրել։ Նույն
տիպի սխալներ են չհայտարարված անունի օգտագործումը, նույն անունի կրկնակի 
հայտարարությունը, ենթածրագրի՝ սխալ արգումենտներով կանչը, ոչ տրամաբանական 
պայմանը, առանց արժեքի ավարտվող ֆունկցիան, և այլն։

## Մի ամբողջական օրինակ

Հիմա արդեն կարող ենք կարդալ մի քիչ ավելի մեծ Կեռաս ծրագիր։ Այն լրացնում է
թվերի զանգվածը քառակուսիներով, հաշվում դրանց գումարը և արդյունքը համեմատում
օգտագործողի ներմուծած սահմանի հետ։ Օրինակում կան լեզվի գրեթե բոլոր հիմնական
կառուցվածքները, բայց ոչ մի նոր կանոն։

```cerasus
' values զանգվածը լրացնել 1, 4, 9, ... թվերով
SUB FillSquares(values[] AS REAL, count AS REAL)
    FOR index = 0 TO count - 1
        LET values[index] = (index + 1)^2
    END FOR
END SUB

' հաշվել զանգվածի առաջին count տարրերի գումարը
SUB Sum(values[] AS REAL, count AS REAL) AS REAL
    DIM index AS REAL
    DIM result AS REAL

    LET index = 0
    LET result = 0
    WHILE index < count
        LET result = result + values[index]
        LET index = index + 1
    END WHILE

    RETURN result
END SUB

' ստուգել՝ արդյոք թիվը մեծ է տրված արժեքից
SUB IsLarge(value AS REAL, limit AS REAL) AS BOOL
    RETURN value > limit
END SUB

SUB Main
    DIM values[8] AS REAL
    DIM count AS REAL
    DIM limit AS REAL
    DIM total AS REAL
    DIM large AS BOOL
    DIM message AS TEXT

    LET count = 8
    CALL FillSquares values, count
    LET total = Sum(values, count)

    CALL Print "Ներմուծիր համեմատման սահմանը։"
    LET limit = NUM(Input())
    LET large = IsLarge(total, limit)

    IF large THEN
        LET message = "Գումարը մեծ է սահմանից։"
    ELSEIF total = limit THEN
        LET message = "Գումարը հավասար է սահմանին։"
    ELSE
        LET message = "Գումարը փոքր է սահմանից։"
    END IF

    CALL Print message
    CALL Print total
END SUB
```

Ծրագրի կատարումը սկսվում է `Main`-ից։ `values`-ը ութ թվերի զանգված է, որի
բոլոր տարրերը սկզբում զրո են։ `FillSquares` պրոցեդուրան զանգվածը ստանում է
հղումով և `FOR` ցիկլով փոխում նրա տարրերը։ `Sum` ֆունկցիան նույն զանգվածը
կարդում է `WHILE` ցիկլով ու վերադարձնում `REAL` արդյունք։ Այնուհետև `Main`-ը
տեքստ է ներմուծում, `NUM`-ով դարձնում թիվ, կանչում է `IsLarge` ֆունկցիան և
`IF` հրամանով ընտրում երեք հաղորդագրություններից մեկը։

Այս նույն ծրագրի կամ նրա առանձին հատվածների ճանապարհին դեռ կհետևենք։ Բառային 
վերլուծիչը տեքստից կառանձնացնի `SUB`, `IDENT`, `REAL` և մյուս բառային տարրերը։
Շարահյուսական վերլուծիչը դրանցից կկառուցի ենթածրագրերի, հրամանների ու 
արտահայտությունների ծառը։ Իմաստային վերլուծիչը `values`-ի ամեն կիրառություն 
կկապի ճիշտ պարամետրի կամ հայտարարության հետ և կստուգի գործողությունների տիպերը։ 
Իսկ կոդի գեներատորը վերջում այդ արդեն հասկացված ծրագիրը կդարձնի կատարվող կոդ։
