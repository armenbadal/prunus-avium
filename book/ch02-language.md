# Կեռաս լեզուն

_Կեռասը_ Բեյսիկ լեզվի նմանությամբ ստեղծված շատ փոքր լեզու է՝ նախատեսված 
իմ գրքում ծրագրավորման լեզվի կոմպիլյատոր իրականացնելը նկարագրելու համար։ 
Ինչպես արդեն ներածությունում նշեցի, Կեռասը միտումնավոր է նախագծված նվազագույն
հնարավորություններով ու երբեմն էլ հնացած, ժամանակակից ծրագրավորման լեզուներին
չնմանվող բաղադրիչներով։ Այն ունի երեք պարզ տիպ, փոփոխականներ ու միաչափ 
զանգվածներ, ճյուղավորման և կրկնության հրամաններ, ֆունկցիաներ ու պրոցեդուրաներ։ 
Այսքանը բավական է ոչ միայն օգտակար փոքր ծրագրեր գրելու, այլև կոմպիլյատորի 
իրականացման գրեթե բոլոր հիմնական խնդիրներին հանդիպելու համար։

Հենց այս պահից ընթերցողին առաջարկում եմ լեզվի նախագծման ու իրականացման բոլոր 
թերությունները, անհարմարություններն ու սխալները համարել ինքնուրույն կատարելու
վարժություններ։ Այս մասին դեռ էլի կխոսեմ [Լեզվի ընդլայնման նախագծեր](ch09-projects.md)
գլխում։ 

Այս գլխում լիարժեք ու վերջնական կսահմանեմ Կեռաս լեզուն։ Կսահմանեմ ոչ միայն դրա
շարահյուսությունը, այլ նաև սեմանտիկան։ Իսկ հետագա գլուխներում, երբ անհրաժեշտ
կլինի իրականացման ինչ-որ որոշում կայացնել, հիմք կընդունեմ այս գլխում սահմանվածը։
Ուրեմն այս գլուխը մեր հետագա աշխատանքի հիմնական «պայմանագիրն» է․ երբ  բառային 
վերլուծիչը պետք է որոշի, թե որտեղ է ավարտվում թիվը, շարահյուսական վերլուծիչը՝ ինչպես 
է կառուցված `IF` հրամանը, իսկ իմաստային վերլուծիչը՝ կարելի՞ է արդյոք թվին տեքստ 
վերագրել, պատասխանը պետք է փնտրել հենց այստեղ։


## Առաջին Կեռաս ծրագրերը

Ծրագրավորման լեզուներին ծանոթանալիս ավանդույթ է դարձել առաջինը գրել աշխարհքին
ողջունող ծրագիր։ Ահա այն Կեռաս լեզվով.

```basic
SUB Main
    CALL Print "Hello, world!"
END SUB
```

Սահմանված է `Main` անունով ենթածրագիրը, որի մարմնում `CALL` հրամանով
`Print` ենթածրագիրը կանչվում է `Hello, world!` տողի համար։

Համաձայնեք, որ այս երեք տողը ոչ մի իրական պատկերացում չեն տալիս լեզվի
հատկությունների մասին։ Բերենք մի ուրիշ օրինակ. ենթածրագիր, որը հաշվում է
տրված երկու վեկտորների սկալյար արտադրյալը.

```basic
SUB Scalar(u[] AS REAL, v[] AS REAL) AS REAL
    IF LEN(u) <> LEN(v) THEN
        RETURN 0
    END IF

    DIM result AS REAL
    FOR i = 0 TO LEN(a) - 1
        LET result = result + a[i] * b[i]
    END FOR

    RETURN result
END SUB
```

Այս օրինակն արդեն ավելի շատ բան է ասում լեզվի հնարավորությունների մասին։
Ենթածրագիրը սկսվում է `SUB` բառով և ավարտվում է `END SUB`-ով։ Փոփոխականը
սահմանվում է `DIM` հրամանով, արժեքը վերագրվում է `LET`-ով, պայմանական
կատարումը գրվում է `IF`-ով, իսկ `FOR` հրամանով կազմակերպվում է պարամետրով
կրկնություն։ Կեռասում հրամանն ավարտվում է տողի հետ։


## Բեկուսի—Նաուրի ընդլայնված նոթագրությունը

Լեզվի շարահյուսական կառուցվածքը նկարագրելու համար օգտագործել եմ Բեկուսի-Նաուրի
ընդլայնված նոթագրությունը։ Այդտեղ ամեն մի հավասարություն կամ կանոն `=` նիշով
բաժանված է ձախ ու աջ մասերի։ Ձախ կողմում նկարագրվող կառուցվածքի անունն է, իսկ 
աջ կողմում՝ նրա հնարավոր տեսքերը։ Օրինակ.

```ebnf
TypeName = 'REAl' | 'TEXT' | 'BOOL'.
```

Ուղղաձիգ գիծը նշանակում է «կամ», հետևաբար `TypeName`-ը կարող է լինել `BOOL`, 
`REAL` կամ `TEXT` տարբերակներից որևէ մեկը։ Ապաթարցերի մեջ վերցրած բառերն ու 
նիշերը ծրագրում պետք է հանդիպեն հենց այդ տեսքով։ Մեծատառերով, բայց առանց 
ապաթարցերի գրված `IDENT`, `NUMBER`, `STRING`, `NEWLINE` և `EOF` անունները 
առանձին սահմանվող կամ նախապես որոշված բառային (լեքսիկական) տարրեր են։

EBNF-ի մյուս պայմանական նշաններն են․

| Գրառում  | Իմաստ |
|:--------:|:------|
| `[ X ]`  | `X`-ը կարող է լինել կամ չլինել |
| `{ X }`  | `X`-ը կարող է կրկնվել զրո կամ ավելի անգամ |
| `( X )`  | `X`-ը դիտարկվում է որպես մեկ խումբ |
| `X Y`    | `X`-ին անմիջապես հաջորդում է `Y`-ը |
| `X \| Y` | գրվում է կամ `X`-ը, կամ `Y`-ը |

Մի ուրիշ օրինակ՝

```ebnf
NewLines = NEWLINE { NEWLINE }.
```

Այստեղ `NewLines` ոչ-տերմինալային սիմվոլը սահմանվել է որպես նոր տողին անցնելու
մեկ կամ ավելի նիշ։ 


## Ծրագրի ընդհանուր կառուցվածքը

Կեռաս ծրագիրը ենթածրագրերի հաջորդականություն է։ Դրա ամենավերին մակարդակի
կանոնն այսպիսին է․

```ebnf
Program = [ NewLines ] { Subroutine NewLines } EOF.
```

Ծրագրի սկզբում կարող են լինել դատարկ տողեր։ Դրանցից հետո գրվում են զրո կամ
ավելի ենթածրագրեր, իսկ վերջում հանդիպում է ֆայլի ավարտը՝ `EOF`-ը։ Ձևականորեն
քերականությունը թույլ է տալիս նաև ոչ մի ենթածրագիր չպարունակող դատարկ ֆայլ,
բայց այդպիսի ծրագիր կատարել հնարավոր չէ։ Իմաստային կանոնները պահանջում են
`Main` անունով մուտքի կետ, հետևաբար գործնական Կեռաս ծրագիրը գոնե մեկ
ենթածրագիր ունի։

Ամենավերին մակարդակում կատարվող հրամաններ գրել չի կարելի։ Օրինակ, այս
տեքստը Կեռաս ծրագիր չէ․

```basic
DIM radius AS REAL
LET radius = 5
```

Այդ հրամանները պետք է որևէ ենթածրագրի մարմնում լինեն։ Կեռասը չունի նաև
գլոբալ փոփոխականներ կամ մի ենթածրագրի ներսում սահմանված այլ ենթածրագրեր։
Բոլոր ենթածրագրերը գրվում են իրար կողքի և ծրագրի ամբողջ տարածքում տեսանելի
են։ Հետևաբար կարելի է ենթածրագիրը կանչել նրա սահմանումից առաջ, ինչպես նաև
կարելի է գրել ռեկուրսիվ ֆունկցիա, որն ուղղակի կամ այլ ֆունկցիայի միջոցով
կանչում է ինքն իրեն։


## Բառային տարրերը

Ծրագրի տեքստը նիշերի մի երկար հաջորդականություն է։ Այդ հաջորդականությունից
քերականական կառուցվածքներ ճանաչելուց առաջ պետք է առանձնացնել լեզվի _բառային
տարրերը_՝ անունները, ծառայողական բառերը, հաստատունները, գործողությունների
նշաններն ու կետադրական նիշերը։ Այս գործը հետագայում կատարելու է scanner-ը,
բայց այստեղ պետք է որոշենք, թե նա ինչ է փնտրելու։


### Բացատանիշերն ու նոր տողը

Սովորական բացատը, թաբուլյացիան և `\r` նիշը բաժանում են բառային տարրերն ու
մնացած դեպքերում անտեսվում են։ Այս երեք գրառումները, օրինակ, նույն իմաստն
ունեն․

```basic
LET area = radius * radius
LET area=radius*radius
LET     area = radius     * radius
```

Նոր տողին անցման `\n` նիշն այլ է։ Այն ինքնուրույն `NEWLINE` բառային տարր է և
ավարտում է հրամանը։ Դրա շնորհիվ Կեռասում կետ-ստորակետի կարիք չկա։ Մի քանի
հաջորդական նոր տողեր թույլատրված են, ուստի ծրագրի մասերը կարելի է իրարից
բաժանել դատարկ տողերով։

Մեկ հրամանը մի քանի ֆիզիկական տողերում շարունակելու միջոց Կեռասի բազային
տարբերակը չունի։ Այսպես գրել չի կարելի․

```basic
LET area = 3.1415926 *
    radius^2
```


### Մեկնաբանությունները

Մեկնաբանությունը սկսվում է `'` նիշով և շարունակվում է մինչև տողի վերջը։ Նոր
տողի նիշը մեկնաբանության մաս չէ, որովհետև այն դեռ պետք է ավարտի ընթացիկ
հրամանը։

```basic
' սա ամբողջ տողով մեկնաբանություն է
LET radius = 5  ' սա էլ՝ հրամանին հաջորդող մեկնաբանություն
```

Մեկնաբանության ներսում գրված ցանկացած այլ նիշ անտեսվում է։ Բազմատող
մեկնաբանություններ Կեռասում չկան․ ամեն նոր տողի սկզբում պետք է նորից գրել
`'` նիշը։


### Ծառայողական բառերը

Կեռասի ծառայողական բառերն են․

```text
SUB      END      AS       DIM      LET
IF       THEN     ELSEIF   ELSE
WHILE    FOR      TO       STEP
CALL     RETURN
BOOL     REAL     TEXT
TRUE     FALSE
OR       AND      NOT      MOD
```

Դրանք գրվում են միայն մեծատառերով և զգայուն են տառերի ռեգիստրի նկատմամբ։
Օրինակ, `IF`-ը ծառայողական բառ է, իսկ `If`-ը և `if`-ը՝ սովորական անուններ։
Այս տարբերությունը մի քիչ խիստ կարող է թվալ, բայց scanner-ի աշխատանքը պարզ
ու միարժեք է դարձնում։


### Անունները

Ենթածրագրերի, պարամետրերի, փոփոխականների ու զանգվածների անունները բառային
վերլուծիչի համար `IDENT` տարրեր են։ Անունը սկսվում է լատինական տառով և կարող է
շարունակվել լատինական տառերով ու թվանշաններով․

```text
[A-Za-z][A-Za-z0-9]*
```

Օրինակ՝ `x`, `radius`, `Point2` և `IsPrime` թույլատրելի անուններ են, իսկ
`2nd`, `two_words` ու `շառավիղ` անունները՝ ոչ։ Ընդգծման նիշն էլ Կեռասի
անուններում չի թույլատրվում։

Անունները նույնպես զգայուն են ռեգիստրի նկատմամբ։ `radius`, `Radius` և
`RADIUS` երեք տարբեր անուններ են։ Ծառայողական բառի ճշգրիտ գրառումը որպես անուն
օգտագործել չի կարելի, որովհետև scanner-ն այն կճանաչի որպես ծառայողական բառ։


### Թվային հաստատունները

Կեռասի բոլոր թվային հաստատունները տասական են և ունեն հետևյալ տեսքը․

```text
[0-9]+(\.[0-9]+)?
```

Այս կանոնին համապատասխանում են `0`, `17`, `3.14` և `1981.06` թվերը։ Թվի
ամբողջ մասը պարտադիր է, իսկ եթե գրված է կետը, ապա կոտորակային մասը նույնպես
պարտադիր է։ Հետևաբար `.5` և `5.` գրառումները ճիշտ թվային հաստատուններ չեն։
Գիտական գրառում, օրինակ՝ `6.02e23`, բազային Կեռասում նույնպես չկա։

Բացասական հաստատուն առանձին բառային տարր չէ։ `-3.14` գրառումը կազմված է
մինուսի գործողությունից և `3.14` դրական հաստատունից։ Այս տարբերությունը կարևոր
է դառնալու արտահայտությունների ծառը կառուցելիս։


### Տեքստային հաստատունները

Տեքստային հաստատունը `"` չակերտների միջև վերցրած նիշերի հաջորդականություն է․

```basic
"Կեռաս"
"Ողջո՜ւյն քեզ, աշխա՛րհք։"
""
```

Վերջին օրինակը դատարկ տողն է։ Բացող ու փակող չակերտներն արժեքի մաս չեն
կազմում։ Տեքստային հաստատունի ներսում նոր տող ու `"` նիշ գրել չի կարելի։
Կեռասի այս տարբերակը չունի նաև հատուկ նիշերի `escape` գրառումներ, հետևաբար
տեքստի ներսում չակերտ կամ նոր տող ներկայացնելու եղանակ առայժմ չկա։

Մեկնաբանություն սկսող ապաթարցը չակերտների ներսում սովորական նիշ է․

```basic
LET message = "Կեռասի ' նշանը"
```


### Տրամաբանական հաստատուններն ու մնացած նշանները

`TRUE` և `FALSE` բառերը համապատասխանաբար _ճշմարիտ_ ու _կեղծ_ տրամաբանական
արժեքներն են։ Scanner-ը դրանք ճանաչում է որպես տրամաբանական հաստատուններ, ոչ
թե սովորական ծառայողական բառեր։

Լեզվի գործողությունների և կետադրության նշաններն են․

```text
=   <>   <   <=   >   >=
+   -    *   /    \    ^    &
(   )    [   ]    ,
```

Մեկ կամ երկու նիշից կազմված այս տարրերի նշանակությունը կբացվի
արտահայտությունների բաժնում։ Այժմ միայն նկատենք, որ `=` նիշը երկու դեր ունի․
`LET` և `FOR` հրամաններում այն կառուցվածքի բաժանիչ է, իսկ արտահայտության մեջ՝
հավասարության ստուգման գործողություն։ Դերը որոշվում է հանդիպման տեղից։


## Տիպերն ու արժեքները

Կեռասը _ստատիկ տիպավորմամբ_ լեզու է։ Ամեն փոփոխականի, պարամետրի և
արտահայտության տիպը որոշվում է մինչև ծրագրի կատարումը։ Եթե, օրինակ, `radius`
փոփոխականը հայտարարվել է որպես թիվ, ապա նրան տեքստ վերագրել չի կարելի։

Լեզվի պարզ տիպերը երեքն են․

```ebnf
TypeName = 'BOOL' | 'REAL' | 'TEXT'.
```

`BOOL` տիպի արժեքները `TRUE`-ն ու `FALSE`-ն են։ Դրանք օգտագործվում են
պայմանների և տրամաբանական գործողությունների համար։ `REAL`-ը Կեռասի միակ
թվային տիպն է։ Անունից երևում է, որ այն կարող է ներկայացնել և՛ ամբողջ, և՛
կոտորակային թվեր։ Առանձին ամբողջաթիվ տիպ չունենք։ `TEXT` տիպի արժեքները
տեքստի տողերն են։

| Տիպ | Օրինակ արժեքներ | Լռելության արժեք |
|:----|:---------------|:-----------------|
| `BOOL` | `TRUE`, `FALSE` | `FALSE` |
| `REAL` | `0`, `-17`, `3.14` | `0` |
| `TEXT` | `"Կեռաս"`, `""` | `""` |

`DIM`-ով սահմանված պարզ փոփոխականն անմիջապես ստանում է աղյուսակում նշված
լռելության արժեքը։ Զանգվածի բոլոր տարրերը նույնպես արժեքավորվում են իրենց
պարզ տիպի լռելության արժեքով։ Այս կանոնը ծրագրում անորոշ արժեքներ չի թողնում։

Կեռասը տիպերի անբացահայտ ձևափոխություններ չի կատարում։ `TRUE`-ն թիվ չէ,
`0`-ն՝ տրամաբանական արժեք, իսկ `"17"`-ը՝ թիվ։ Եթե ներմուծված `"17"` տեքստը
պետք է օգտագործել որպես թիվ, այն բացահայտ ձևով պետք է փոխակերպել `NUM`
ֆունկցիայով։ Նույն խստությունն է գործում վերագրումների, գործողությունների,
ենթածրագրերի արգումենտների և վերադարձվող արժեքների համար։

Պարզ տիպից բացի Կեռասն ունի նաև միաչափ զանգվածի տիպ։ Օրինակ՝ `REAL[]`-ը
թվերի, իսկ `TEXT[]`-ը տեքստերի զանգված է։ Ծրագրի տեքստում այս ձևը որպես
ինքնուրույն տիպի անուն չի գրվում․ զանգված լինելը երևում է փոփոխականի կամ
պարամետրի անվանը հաջորդող `[]` փակագծերից։ Զանգվածն ամբողջությամբ պարզ արժեք
չէ։ Այն չի կարելի ամբողջությամբ վերագրել, վերադարձնել ֆունկցիայից կամ տալ
պարզ արժեք սպասող գործողությանը։ Կարելի է աշխատել նրա առանձին տարրերի հետ և
զանգվածը փոխանցել համապատասխան զանգվածային պարամետրին։


## Անուններն ու տեսանելիության տիրույթները

Կեռաս ծրագրում անուն ունեն ենթածրագրերը, դրանց պարամետրերը, `DIM`-ով
հայտարարված փոփոխականներն ու զանգվածները և `FOR` ցիկլի հաշվիչը։ Անունը
օգտագործելու պահին կոմպիլյատորը պետք է կարողանա այն կապել ճիշտ հայտարարության
հետ։

Ենթածրագրերի անունները գտնվում են ծրագրի _գլոբալ տեսանելիության տիրույթում_։
Միևնույն անունով երկու ենթածրագիր սահմանել չի կարելի։ Ներդրված
ենթածրագրերի՝ `Print`, `Input`, `NUM` և `SQR` անունները նույնպես զբաղված են և
վերասահմանման ենթակա չեն։

Ամեն ենթածրագրի մարմին կազմում է տեղային անունների մի տիրույթ։ Դրա մեջ են
ենթածրագրի պարամետրերը, բոլոր `DIM` հայտարարությունները և `FOR`-ի ներմուծած
հաշվիչները։ Ներդրված `IF`, `WHILE` և `FOR` բլոկները նոր տիրույթ չեն ստեղծում։
Ուրեմն ճյուղի կամ ցիկլի մարմնում հայտարարված փոփոխականը պատկանում է ամբողջ
ենթածրագրին, և նույն անունը մեկ այլ ճյուղում նորից հայտարարել չի կարելի։

Օրինակ՝ հետևյալ ծրագրում `value` անունը երկու անգամ է հայտարարված նույն
ենթածրագրում․

```basic
SUB Main
    DIM value AS REAL
    IF TRUE THEN
        DIM value AS TEXT
    END IF
END SUB
```

Սա իմաստային սխալ է, նույնիսկ եթե երկու հայտարարությունները տեքստում տարբեր
բլոկների ներսում են։ Այս պարզ կանոնի շնորհիվ Կեռասի կոմպիլյատորին հարկավոր չէ
ղեկավարել իրար մեջ ներդրված տեղային տիրույթների բարդ համակարգ։

Փոփոխականի անունը պետք է բացահայտ հայտարարված լինի `DIM`-ով կամ որպես
պարամետր, եթե այն `FOR`-ի կողմից ներմուծված հաշվիչ չէ։ `LET` հրամանը նոր
փոփոխական չի ստեղծում։

```basic
SUB Main
    LET radius = 5  ' ՍԽԱԼ․ radius անունը սահմանված չէ
END SUB
```

Ենթածրագրերի և տեղային փոփոխականների անունները տարբեր դերեր ունեն։ Կանչի
տեղում որոնվում է ենթածրագիր, իսկ սովորական արտահայտության կամ վերագրման
տեղում՝ փոփոխական։ Այդ պատճառով ֆունկցիայի պարամետրը նույնիսկ կարող է ունենալ
ֆունկցիայի անունը, թեև ընթեռնելի ծրագրում այդպիսի համընկնումից սովորաբար լավ է
խուսափել։


## Հրամանների հաջորդականությունը

Ենթածրագրերի ու ղեկավարող կառուցվածքների մարմինները կազմված են իրար հաջորդող
հրամաններից։ Այդպիսի մարմինը քերականության մեջ անվանում ենք `Sequence`․

```ebnf
Sequence = NewLines { Statement NewLines }.
NewLines = NEWLINE { NEWLINE }.
```

Մարմինը սկսվում է նոր տողով։ Ամեն հրամանից հետո նույնպես պետք է լինի գոնե մեկ
նոր տող։ Դատարկ տողերը կարող են հանդիպել հրամաններից առաջ, հետո և նրանց միջև։
Հրամանների դատարկ հաջորդականությունն էլ թույլատրելի է․

```basic
SUB Nothing
END SUB
```

Կեռասն ունի յոթ տեսակի հրաման․

```ebnf
Statement = Dim | Let | If | While | For | Call | Return.
```

Դրանք են փոփոխական հայտարարող `DIM`-ը, արժեք վերագրող `LET`-ը,
ճյուղավորման `IF`-ը, նախապայմանով `WHILE` ցիկլը, հաշվիչով `FOR` ցիկլը,
պրոցեդուրայի `CALL` կանչը և ֆունկցիայից արժեք վերադարձնող `RETURN`-ը։


## Փոփոխականներն ու զանգվածները

Փոփոխականը կամ զանգվածը հայտարարվում է `DIM` հրամանով․

```ebnf
Dim = 'DIM' IDENT [ '[' Expression ']' ] 'AS' TypeName.
```

Պարզ փոփոխականի համար գրվում են նրա անունն ու տիպը․

```basic
DIM radius AS REAL
DIM message AS TEXT
DIM ready AS BOOL
```

Այս հայտարարություններից հետո `radius`-ի արժեքը `0` է, `message`-ինը՝ դատարկ
տող, իսկ `ready`-ինը՝ `FALSE`։ Սկզբնական այլ արժեք տալու համար պետք է առանձին
`LET` հրաման գրել։ Հայտարարության մեջ արժեքավորման գրառում Կեռասում չկա։

Եթե անունից հետո քառակուսի փակագծերում տրված է չափը, սահմանվում է միաչափ
զանգված․

```basic
DIM values[100] AS REAL
DIM words[2 * count] AS TEXT
DIM flags[limit + 1] AS BOOL
```

Չափը կարող է լինել հաստատուն կամ կատարման ժամանակ հաշվարկվող արտահայտություն։
Այն պետք է տա դրական, վերջավոր ու ամբողջ արժեք ունեցող `REAL` թիվ։ Օրինակ՝
`6`, `2 * 3` և `length` արժեքները կարող են ճիշտ չափեր լինել, իսկ `0`, `-4`,
`2.5`, `TRUE` կամ `"շատ"` արժեքները՝ ոչ։ Չափը հաշվվում է հայտարարության
կատարման պահին և դրանից հետո չի փոխվում։

Զանգվածի տարրերը համարակալվում են զրոյից։ Եթե զանգվածի չափը `n` է, թույլատրելի
ինդեքսներն են `0`-ից մինչև `n - 1`։ Ինդեքսը պետք է տա ամբողջ արժեք ունեցող
`REAL` թիվ։ Տարրին դիմում ենք անունից հետո ինդեքսը քառակուսի փակագծերում
գրելով․

```basic
LET values[0] = 3.14
LET values[k + 1] = values[k] * 2
```

Չափից դուրս ինդեքսը չի կարող հայտնաբերվել միայն տիպերի ստուգմամբ, որովհետև
ինդեքսի ու չափի արժեքները հաճախ հայտնի են դառնում կատարման ժամանակ։ Այդպիսի
դիմումը Կեռաս ծրագրի կատարման սխալ է։

Զանգվածը կարելի է փոխանցել ենթածրագրին, բայց չի կարելի ամբողջությամբ նոր
արժեքով փոխարինել․

```basic
DIM left[10] AS REAL
DIM right[10] AS REAL
LET left = right  ' ՍԽԱԼ․ ամբողջ զանգվածին վերագրում չկա
```


## Վերագրման հրամանը

`LET` հրամանը նոր արժեք է գրում պարզ փոփոխականի կամ զանգվածի մի տարրի մեջ․

```ebnf
Let = 'LET' IDENT [ '[' Expression ']' ] '=' Expression.
```

Օրինակ՝

```basic
LET radius = 5
LET area = 3.1415926 * radius^2
LET ready = area > 0
LET words[index] = "Կեռաս"
```

Հավասարության ձախ կողմի անունը պետք է նախապես սահմանված լինի։ Եթե գրված է
ինդեքս, անունը պետք է զանգված լինի, իսկ եթե ինդեքս չկա՝ պարզ փոփոխական։ Աջ
կողմի արտահայտության տիպը պետք է ճիշտ նույնը լինի, ինչ ձախ կողմի ընդունած
արժեքի տիպը։

```basic
DIM radius AS REAL
LET radius = TRUE  ' ՍԽԱԼ․ BOOL արժեքը չի կարելի վերագրել REAL-ին
```

Այս վերջին հրամանը քերականորեն ճիշտ է։ Այն ունի `LET` բառը, անունը,
հավասարության նշանն ու ճիշտ կառուցված արտահայտությունը։ Սխալը պարզվում է միայն
անունը նրա հայտարարության հետ կապելուց ու երկու կողմերի տիպերը համեմատելուց
հետո։ Ուրեմն _շարահյուսորեն ճիշտ_ դեռ չի նշանակում _իմաստաբանորեն ճիշտ_։ Այս
տարբերությանը հետագա գլուխներում դեռ շատ ենք հանդիպելու։


## Արտահայտությունները

Արտահայտությունը հաշվարկ է, որն ավարտվում է որևէ արժեքով։ Պարզագույն
արտահայտությունները հաստատուններն ու փոփոխականներն են․

```basic
3.14
"Կեռաս"
TRUE
radius
```

Դրանցից գործողությունների միջոցով կառուցվում են ավելի բարդ
արտահայտություններ․

```basic
3.1415926 * radius^2
name & " լեզու"
(x >= 0) AND (x <= 10)
values[index + 1]
CircleArea(radius)
```

Քերականության սկզբնական կանոնն է․

```ebnf
Expression = Disjunction.
```

`Disjunction`-ից մինչև `Factor` տանող կանոնների շղթան ոչ միայն նկարագրում է
արտահայտության թույլատրելի տեսքը, այլև որոշում գործողությունների
նախապատվությունն ու զուգորդականությունը։ Ստորև աղյուսակում գործողությունները
դասավորված են ցածր նախապատվությունից դեպի բարձր։

| Գործողություններ | Օպերանդների տիպերը | Արդյունքը |
|:-----------------|:--------------------|:----------|
| `OR` | `BOOL`, `BOOL` | `BOOL` |
| `AND` | `BOOL`, `BOOL` | `BOOL` |
| `NOT` | `BOOL` | `BOOL` |
| `=`, `<>` | նույն պարզ տիպի երկու արժեք | `BOOL` |
| `>`, `>=`, `<`, `<=` | երկու `REAL` կամ երկու `TEXT` | `BOOL` |
| `+`, `-` | `REAL`, `REAL` | `REAL` |
| `&` | `TEXT`, `TEXT` | `TEXT` |
| `*`, `/`, `\`, `MOD` | `REAL`, `REAL` | `REAL` |
| `^` | `REAL`, `REAL` | `REAL` |
| միտեղանի `+`, `-` | `REAL` | `REAL` |
| `a[i]` | զանգված և `REAL` ինդեքս | տարրի պարզ տիպը |
| `f(...)` | ըստ ֆունկցիայի պարամետրերի | ֆունկցիայի պարզ տիպը |

Աղյուսակը կարդալու համար դիտարկենք `2 + 3 * 4` արտահայտությունը։
Բազմապատկման նախապատվությունն ավելի բարձր է, քան գումարմանը, հետևաբար նախ
հաշվվում է `3 * 4`-ը, ապա արդյունքին գումարվում է `2`-ը։ Արտահայտության արժեքը
`14` է, ոչ թե `20`։ Սովորական փակագծերով միշտ կարելի է բացահայտ փոխել կամ
պարզապես ընդգծել հաշվարկման կարգը․

```basic
(2 + 3) * 4
```

Հիմա գործողությունների խմբերը դիտարկենք առանձին։


### Տրամաբանական գործողությունները

`NOT`-ը ժխտում է մեկ տրամաբանական արժեք։ `AND`-ը ճշմարիտ է միայն այն դեպքում,
երբ երկու օպերանդներն էլ ճշմարիտ են, իսկ `OR`-ը՝ երբ դրանցից գոնե մեկը
ճշմարիտ է։

```basic
NOT finished
ready AND valid
empty OR failed
```

`AND` և `OR` գործողությունները հաշվարկվում են _կարճ հաշվարկման սխեմայով_։ Եթե
`AND`-ի ձախ օպերանդը `FALSE` է, ամբողջ արտահայտությունն արդեն կեղծ է, և աջ
օպերանդը չի հաշվարկվում։ Նույն կերպ, եթե `OR`-ի ձախ օպերանդը `TRUE` է, աջն
այլևս հաշվելու կարիք չկա։ Այս հատկությունը թույլ է տալիս ոչ միայն խնայել
ավելորդ աշխատանքը, այլև անվտանգ գրել այսպիսի պայման․

```basic
(index < count) AND (values[index] > 0)
```

Եթե `index`-ը սահմանն անցել է, զանգվածի տարրին դիմող երկրորդ մասը չի
կատարվի։

`NOT`-ի նախապատվությունը համեմատման գործողություններից ցածր է։ Այսինքն՝

```basic
NOT x = 0
```

գրառումը մեկնաբանվում է որպես `NOT (x = 0)`։ Այնուամենայնիվ, բացահայտ
փակագծերն այստեղ ընթերցողի գործը հեշտացնում են։


### Հավասարությունն ու համեմատումը

`=` գործողությունը ստուգում է երկու արժեքների հավասարությունը, իսկ `<>`-ը՝
անհավասարությունը։ Դրանց օպերանդները կարող են լինել ցանկացած պարզ տիպի, բայց
պետք է նույնատիպ լինեն։

```basic
count = 0
name <> ""
ready = TRUE
```

`>`, `>=`, `<` և `<=` գործողությունները համեմատում են թվեր կամ տեքստեր։ Երկու
օպերանդներն այստեղ էլ նույնատիպ պետք է լինեն։ Թվերը համեմատվում են իրենց
թվային արժեքով, իսկ տեքստերը՝ բառարանային կարգով։ `BOOL` արժեքների կարգային
համեմատություն չկա։

```basic
temperature < 0
name >= "K"
```

Կեռասը շղթայված համեմատություններ չունի։ `0 < x < 10` գրառման փոխարեն պետք է
գրել․

```basic
(0 < x) AND (x < 10)
```


### Թվաբանական գործողությունները

Բինար `+`, `-`, `*`, `/` և `^` գործողությունները համապատասխանաբար գումարում,
հանում, բազմապատկում, բաժանում ու աստիճան բարձրացում են։ Դրանց երկու
օպերանդներն ու արդյունքը `REAL` տիպի են։

```basic
a + b
a - b
a * b
a / b
a^b
```

`\` գործողությունը կատարում է բաժանում և քանորդը կտրում է դեպի զրոն։ Քանի որ
Կեռասը չունի առանձին ամբողջաթիվ տիպ, արդյունքը դարձյալ `REAL` է, պարզապես ունի
զրոյական կոտորակային մաս։ `MOD`-ը վերադարձնում է բաժանման մնացորդը և նույնպես
`REAL` արդյունք ունի։ Օրինակ՝ `17 \ 5`-ի արժեքը `3` է, իսկ `17 MOD 5`-ինը՝
`2`։

`^` գործողությունն աջ-զուգորդական է։ Ուրեմն `2^3^2` գրառումը նշանակում է
`2^(3^2)`։ Մնացած բինար թվաբանական գործողությունները ձախ-զուգորդական են․
`10 - 3 - 2`-ը նույնն է, ինչ `(10 - 3) - 2`։

Միտեղանի `+` և `-` գործողությունները համապատասխանաբար պահպանում և փոխում են
թվի նշանը։ Մի քանի այդպիսի գործողություններ կարելի է գրել իրար հետևից․

```basic
--value
-+-value
```


### Տեքստերի կցումը

`&` գործողությունը երկու `TEXT` արժեք կցում է իրար և վերադարձնում նոր տեքստ․

```basic
"Կեռաս" & " լեզու"
firstName & " " & lastName
```

Թվին կամ տրամաբանական արժեքին տեքստ անբացահայտ կցել չի կարելի։ Այդպիսի
հարմարություն ավելացնելու համար լեզվին պետք կլինի, օրինակ, թիվը տեքստի
փոխակերպող առանձին ֆունկցիա։


### Ինդեքսավորումն ու ֆունկցիայի կիրառությունը

Զանգվածի տարրին դիմելու գործողության ձախ կողմում զանգված է, իսկ քառակուսի
փակագծերում՝ ամբողջ արժեք ունեցող `REAL` արտահայտություն։ Արդյունքի տիպը
զանգվածի տարրերի տիպն է․

```basic
values[0]
values[index + 1]
words[count - 1]
```

Ֆունկցիան արտահայտության մեջ կիրառելիս նրա անունից հետո սովորական փակագծերում
գրվում են ստորակետով բաժանված արգումենտները․

```basic
Input()
SQR(2)
Maximum(x, y)
Sum(values, count)
```

Նույնիսկ արգումենտ չունեցող ֆունկցիայի դեպքում `()` փակագծերը պարտադիր են։
Դրանցով ֆունկցիայի կիրառությունը տարբերվում է նույնանուն փոփոխականից։
Արգումենտների քանակը, հերթականությունը, պարզ կամ զանգվածային լինելն ու տիպերը
պետք է համապատասխանեն ֆունկցիայի պարամետրերին։ Արտահայտության արդյունքը
ֆունկցիայի հայտարարված վերադարձվող պարզ տիպն է։


### Արտահայտությունների ամբողջ քերականությունը

Ասվածը հիմա հավաքենք ձևական կանոնների մեջ․

```ebnf
Expression     = Disjunction.
Disjunction    = Conjunction { 'OR' Conjunction }.
Conjunction    = Negation { 'AND' Negation }.
Negation       = { 'NOT' } Equality.
Equality       = Comparison [ ('=' | '<>') Comparison ].
Comparison     = Addition [ ('>' | '>=' | '<' | '<=') Addition ].
Addition       = Multiplication { ('+' | '-' | '&') Multiplication }.
Multiplication = Power { ('*' | '/' | '\' | 'MOD') Power }.
Power          = Unary [ '^' Power ].
Unary          = { ('+' | '-') } Subscript.
Subscript      = Factor [ '[' Expression ']' ].
Factor         = 'TRUE' | 'FALSE' | NUMBER | STRING
               | IDENT [ '(' [ ExpressionList ] ')' ]
               | '(' Expression ')'.

ExpressionList = Expression { ',' Expression }.
```

Այստեղ `Power` կանոնի աջ կողմում նորից `Power` ունենալն է աստիճանի
գործողությունը աջ-զուգորդական դարձնում։ Իսկ `Addition`-ի ու
`Multiplication`-ի կրկնությունները համապատասխան գործողությունները
ձախ-զուգորդական են դարձնում։ Այս մանրուքը հետագայում ուղղակիորեն կերևա
parser-ի կոդում ու կառուցված AST-ում։


## Պայմանական կատարումը

Ծրագրի ընթացքը տվյալներից կախված ճյուղավորելու համար Կեռասն ունի `IF`
հրամանը։ Դրա ամենապարզ տեսքն է․

```basic
IF temperature < 0 THEN
    CALL Print "Ցուրտ է։"
END IF
```

`IF`-ին հաջորդող արտահայտությունը պետք է `BOOL` արժեք տա։ Եթե այդ արժեքը
`TRUE` է, կատարվում է `THEN`-ից հետո գրված մարմինը, իսկ եթե `FALSE` է՝ մարմինը
բաց է թողնվում։ `0` թիվը կամ դատարկ տեքստը Կեռասում կեղծ արժեքներ չեն, ուստի
դրանք որպես պայման օգտագործել չի կարելի։

Երկու այլընտրանք ընտրելու համար ավելացվում է `ELSE` ճյուղը․

```basic
IF number MOD 2 = 0 THEN
    CALL Print "զույգ"
ELSE
    CALL Print "կենտ"
END IF
```

Իսկ մի քանի պայման հերթով ստուգելու համար կարելի է գրել ցանկացած քանակով
`ELSEIF` ճյուղեր․

```basic
IF value < 0 THEN
    LET sign = -1
ELSEIF value > 0 THEN
    LET sign = 1
ELSE
    LET sign = 0
END IF
```

Պայմանները հաշվվում են վերևից ներքև։ Կատարվում է առաջին ճշմարիտ պայմանին
համապատասխան մարմինը, իսկ հաջորդ ճյուղերն այլևս չեն դիտարկվում։ Եթե ոչ մի
պայման ճշմարիտ չէ, կատարվում է `ELSE` մարմինը, եթե այն կա։

Ամբողջ կանոնն այսպիսին է․

```ebnf
If = 'IF' Expression 'THEN' Sequence
     { 'ELSEIF' Expression 'THEN' Sequence }
     [ 'ELSE' Sequence ]
     'END' 'IF'.
```

`IF`, `ELSEIF` և `ELSE` մարմինները նոր անունների տիրույթ չեն ստեղծում։ Դրանց
ներսում գրված `DIM` հայտարարությունները պատկանում են ամբողջ ենթածրագրին։


## `WHILE` ցիկլը

Երբ որևէ հրամանների խումբ պետք է կրկնել այնքան ժամանակ, քանի դեռ տրված պայմանը
ճշմարիտ է, օգտագործվում է `WHILE` ցիկլը․

```ebnf
While = 'WHILE' Expression Sequence 'END' 'WHILE'.
```

Օրինակ, Էվկլիդեսի հանման եղանակով երկու դրական թվերի ամենամեծ ընդհանուր
բաժանարարը կարելի է հաշվել այսպես․

```basic
WHILE x <> y
    IF x > y THEN
        LET x = x - y
    ELSE
        LET y = y - x
    END IF
END WHILE
```

Ամեն իտերացիայից առաջ հաշվվում է `WHILE`-ի պայմանը։ Այն պետք է `BOOL` լինի։
Եթե արժեքը `TRUE` է, կատարվում է մարմինը, ապա պայմանը նորից է հաշվվում։ Երբ
արժեքը դառնում է `FALSE`, ցիկլն ավարտվում է։ Եթե պայմանն առաջին իսկ ստուգման
ժամանակ կեղծ է, մարմինը ոչ մի անգամ չի կատարվի։

Ցիկլի մարմինը նոր տեսանելիության տիրույթ չի ստեղծում։ Կեռասի բազային
տարբերակում չկան նաև ցիկլից հարկադրաբար դուրս գալու կամ հաջորդ իտերացիային
անցնելու `BREAK` և `CONTINUE` հրամաններ։ Անհրաժեշտ ավարտը պետք է կազմակերպել
հենց `WHILE`-ի պայմանով։


## `FOR` ցիկլը

Հայտնի սկզբնական արժեքից մինչև որևէ սահման հաստատուն քայլով շարժվելու համար
ավելի հարմար է `FOR` ցիկլը։

```basic
FOR index = 0 TO 9
    LET values[index] = index^2
END FOR
```

Այստեղ `index` հաշվիչը սկզբում ստանում է `0`, իսկ ամեն իտերացիայից հետո
ավելանում է մեկով։ Վերջնական `9` արժեքը նույնպես ներառված է, հետևաբար մարմինը
կատարվում է տաս անգամ։

Հակառակ ուղղությամբ շարժվելու համար նշվում է բացասական քայլը․

```basic
FOR index = 9 TO 0 STEP -1
    CALL Print values[index]
END FOR
```

Ձևական կանոնն է․

```ebnf
For = 'FOR' IDENT '=' Expression 'TO' Expression
      [ 'STEP' [ '+' | '-' ] NUMBER ]
      Sequence 'END' 'FOR'.
```

Սկզբնական ու վերջնական արժեքները պետք է `REAL` լինեն։ `STEP`-ից հետո կարելի է
գրել միայն դրական կամ բացասական թվային հաստատուն, ոչ թե կամայական
արտահայտություն։ Եթե `STEP` մասը բացակայում է, քայլը `1` է։ Զրոյական քայլն
արգելված է, որովհետև այդպիսի ցիկլը բնական ճանապարհով առաջ չէր շարժվի։

Ցիկլն սկսելուց առաջ սկզբնական արժեքը, վերջնական սահմանն ու քայլը հաշվվում են
մեկ անգամ։ Հաշվիչը ստանում է սկզբնական արժեքը։ Դրական քայլի դեպքում մարմինը
կատարվում է, քանի դեռ հաշվիչը փոքր է կամ հավասար վերջնական սահմանին։ Բացասական
քայլի դեպքում այն կատարվում է, քանի դեռ հաշվիչը մեծ է կամ հավասար սահմանին։
Ամեն իտերացիայից հետո հաշվիչին գումարվում է քայլը։ Եթե սկզբնական արժեքն ու
քայլի ուղղությունը սահմանին հասնելու հնարավորություն չեն տալիս, մարմինը ոչ մի
անգամ չի կատարվում։

`FOR`-ի հաշվիչը պետք է պարզ `REAL` փոփոխական լինի։ Այն կարելի է նախապես
բացահայտ հայտարարել․

```basic
DIM index AS REAL
FOR index = 0 TO 9
    ' ...
END FOR
```

Եթե այդ անունով փոփոխական դեռ չկա, `FOR`-ն ինքն է ներմուծում նոր `REAL`
փոփոխական։ Այդ անբացահայտ հայտարարությունը համարժեք է ենթածրագրում
`DIM index AS REAL` գրելուն, իսկ անունը տեսանելի է ամբողջ ենթածրագրի մարմնում։
Եթե նույն անունով արդեն կա `TEXT`, `BOOL` կամ զանգվածային փոփոխական, այն որպես
`FOR`-ի հաշվիչ օգտագործել չի կարելի։

Հաշվիչը սովորական փոփոխական է, ուստի լեզուն չի արգելում մարմնի ներսում նրան
նոր արժեք վերագրել։ Այդ դեպքում իտերացիայի վերջում քայլը գումարվում է արդեն
փոփոխված արժեքին։ Այս հնարավորությունն օգտագործելիս հեշտ է ստանալ անվերջ կամ
դժվար ընթեռնելի ցիկլ, հետևաբար լավ է հաշվիչը փոխել միայն `FOR`-ի սեփական
քայլով։


## Ենթածրագրերը

Կեռաս ծրագրի հիմնական կառուցվածքային միավորը ենթածրագիրն է։ Այն կարող է լինել
_պրոցեդուրա_, որը որևէ գործողություն է կատարում, կամ _ֆունկցիա_, որը նաև արժեք
է վերադարձնում։ Երկուսն էլ սկսվում են `SUB` բառով ու ավարտվում `END SUB`-ով․

```ebnf
Subroutine = 'SUB' IDENT
             [ '(' [ ParameterList ] ')' ]
             [ 'AS' TypeName ]
             Sequence
             'END' 'SUB'.
```

Ամենապարզ պրոցեդուրան կարող է այսպիսի տեսք ունենալ․

```basic
SUB SayHello
    CALL Print "Ողջո՜ւյն։"
END SUB
```

Արգումենտներ չունեցող ենթածրագրի սահմանման մեջ դատարկ փակագծերը կարելի է և՛
գրել, և՛ բաց թողնել։ `SUB SayHello()` և `SUB SayHello` վերնագրերը համարժեք են։

Պարամետրերը գրվում են փակագծերի մեջ՝ ստորակետերով բաժանված․

```ebnf
ParameterList = Parameter { ',' Parameter }.
Parameter = IDENT [ '[' ']' ] 'AS' TypeName.
```

Օրինակ՝

```basic
SUB PrintMaximum(x AS REAL, y AS REAL)
    IF x > y THEN
        CALL Print x
    ELSE
        CALL Print y
    END IF
END SUB
```

Ամեն պարամետր ունի անուն ու տիպ։ Պարզ պարամետրերը ենթածրագրին փոխանցվում են
արժեքով․ պարամետրի փոփոխությունը կանչողի փոփոխականը չի փոխում։ Զանգվածային
պարամետրի անունից հետո գրվում է դատարկ `[]` զույգը․

```basic
SUB Clear(values[] AS REAL, count AS REAL)
    FOR index = 0 TO count - 1
        LET values[index] = 0
    END FOR
END SUB
```

Պարամետրի հայտարարության մեջ զանգվածի չափ չի գրվում։ Զանգվածը փոխանցվում է
հղումով, հետևաբար `Clear`-ի կատարած փոփոխությունները երևում են նաև կանչող
ենթածրագրում։

Եթե վերնագրում պարամետրերի ցուցակից հետո գրված է `AS` ու պարզ տիպի անուն,
ենթածրագիրը ֆունկցիա է․

```basic
SUB Maximum(x AS REAL, y AS REAL) AS REAL
    IF x > y THEN
        RETURN x
    ELSE
        RETURN y
    END IF
END SUB
```

Եթե վերադարձվող տիպը բացակայում է, ենթածրագիրը պրոցեդուրա է։ Ֆունկցիան կարող
է վերադարձնել միայն պարզ `BOOL`, `REAL` կամ `TEXT` արժեք։ Զանգված վերադարձնել
չի կարելի։

Բոլոր ենթածրագրերի վերնագրերը տեսանելի են ամբողջ ծրագրում՝ անկախ սահմանումների
հերթականությունից։ Օրինակ, `Main`-ը կարող է կանչել ֆայլում իրենից հետո գրված
ենթածրագիրը։ Նույն հատկությունն էլ թույլ է տալիս ռեկուրսիան։


## Պրոցեդուրայի կանչը

Պրոցեդուրան կանչվում է `CALL` հրամանով․

```ebnf
Call = 'CALL' IDENT [ ExpressionList ].
```

Արգումենտները գրվում են անունից հետո, առանց շրջապատող փակագծերի․

```basic
CALL SayHello
CALL PrintMaximum 7, 12
CALL Clear values, count
```

Արգումենտների ցուցակը կարող է դատարկ լինել։ Հակառակ դեպքում արգումենտներն
իրարից բաժանվում են ստորակետերով։ Դրանց քանակը, հերթականությունը, տիպերն ու
պարզ կամ զանգվածային լինելը պետք է համապատասխանեն պարամետրերի ցուցակին։

`CALL`-ով կարելի է կանչել միայն արժեք չվերադարձնող ենթածրագիր՝ պրոցեդուրա։ Եթե
ենթածրագիրը ֆունկցիա է, այն պետք է կիրառել արտահայտության մեջ․

```basic
DIM maximum AS REAL
LET maximum = Maximum(7, 12)
```

Այս տարբերակումը թույլ չի տալիս աննկատ կորցնել ֆունկցիայի հաշվարկած արժեքը և
միաժամանակ պարզ է դարձնում AST-ի երկու տարբեր հանգույցների՝ `Call`-ի ու
`Apply`-ի նշանակությունը։


## Արժեքի վերադարձը

Ֆունկցիայից արժեք վերադարձնելու համար է `RETURN` հրամանը․

```ebnf
Return = 'RETURN' Expression.
```

Արտահայտությունը պետք է պարզ արժեք տա և համապատասխանի ֆունկցիայի վերնագրում
հայտարարված տիպին։ `RETURN`-ը հաշվարկում է այդ արժեքը և անմիջապես ավարտում
ֆունկցիայի կատարումը։

```basic
SUB IsPositive(value AS REAL) AS BOOL
    RETURN value > 0
END SUB
```

Պրոցեդուրայում `RETURN` գրել չի կարելի, որովհետև Կեռասի `RETURN` հրամանը միշտ
արժեք է պահանջում։ Բազային լեզուն չունի միայն ենթածրագրի աշխատանքն ավարտող
դատարկ `RETURN`։

Ֆունկցիայի կատարման բոլոր հնարավոր ուղիները պետք է հասնեն `RETURN` հրամանի։
Հետևյալ ֆունկցիան սխալ է․

```basic
SUB Sign(value AS REAL) AS REAL
    IF value < 0 THEN
        RETURN -1
    END IF
END SUB
```

Երբ `value`-ը բացասական չէ, ֆունկցիան ավարտվում է առանց արժեքի։ Ճիշտ
տարբերակում պետք է ծածկել նաև մնացած ուղիները․

```basic
SUB Sign(value AS REAL) AS REAL
    IF value < 0 THEN
        RETURN -1
    ELSEIF value > 0 THEN
        RETURN 1
    ELSE
        RETURN 0
    END IF
END SUB
```

Ցիկլի ներսում գրված `RETURN`-ը միայնակ չի երաշխավորում արժեքի վերադարձը,
որովհետև ցիկլի մարմինը կարող է ոչ մի անգամ չկատարվել։ Իսկ բոլոր ճյուղերում
արժեք վերադարձնող և պարտադիր `ELSE` ունեցող `IF` հրամանը այդ երաշխիքը տալիս
է։


## Ծրագրի մուտքի կետը

Ամեն Կեռաս ծրագիր պետք է ունենա ճիշտ մեկ `Main` անունով ենթածրագիր։ Ծրագրի
կատարումը սկսվում է դրանից։ `Main`-ը պետք է պրոցեդուրա լինի՝ առանց
պարամետրերի և վերադարձվող տիպի․

```basic
SUB Main
    ' ծրագրի կատարումը սկսվում է այստեղից
END SUB
```

Հետևյալ երկու վերնագրերն իմաստային սխալներ են․

```basic
SUB Main(value AS REAL)  ' Main-ը պարամետր չի կարող ունենալ
END SUB

SUB Main AS REAL         ' Main-ը արժեք չի կարող վերադարձնել
    RETURN 0
END SUB
```

`Main`-ի բացակայությունը նույնպես սխալ է։ Մինչդեռ քերականական վերլուծիչը
կարող է հաջողությամբ կառուցել այդպիսի ֆայլի ծառը․ միայն իմաստային վերլուծության
ժամանակ է պարզվում, որ ծրագրի կատարումը սկսելու տեղ չկա։


## Ներդրված ենթածրագրերը

Առանց ներմուծման, արտածման ու մի քանի տարրական փոխակերպումների լեզվով գրեթե
անհնար է հետաքրքիր օրինակ փորձել։ Այդ պատճառով Կեռասի բազային միջավայրում
նախապես հայտարարված են չորս ենթածրագրեր։ Դրանք սովորական Կեռաս կոդով սահմանել
պետք չէ, իսկ դրանց անունները վերասահմանել չի կարելի։

| Ենթածրագիր | Տեսակ | Նշանակություն |
|:-----------|:------|:--------------|
| `Print(value)` | պրոցեդուրա | արտածում է մեկ պարզ արժեք |
| `Input()` | `TEXT` ֆունկցիա | կարդում և վերադարձնում է ներմուծված տեքստը |
| `NUM(text)` | `REAL` ֆունկցիա | տեքստը փոխակերպում է թվի |
| `SQR(value)` | `REAL` ֆունկցիա | վերադարձնում է թվի քառակուսի արմատը |

`Print`-ին կարելի է տալ ցանկացած պարզ տիպի ճիշտ մեկ արժեք․

```basic
CALL Print "Պատրաստ է։"
CALL Print 3.1415926
CALL Print TRUE
```

Զանգվածն ամբողջությամբ արտածել չի կարելի։ Պետք է ցիկլով դիմել նրա տարրերին։

`Input`-ը պարամետր չունի և միշտ `TEXT` է վերադարձնում։ Թիվ ներմուծելու համար
ստացված տեքստը պետք է բացահայտ փոխակերպել․

```basic
DIM line AS TEXT
LET line = Input()

DIM number AS REAL
LET number = NUM(line)
```

Կամ, ավելի կարճ․

```basic
DIM number AS REAL
LET number = NUM(Input())
```

`SQR`-ը ստանում և վերադարձնում է `REAL` արժեք։ Օրինակ՝ `SQR(9)`-ի արժեքը `3`
է։ Հետագայում այս փոքր ներդրված գրադարանը կարելի է համալրել տեքստային,
մաթեմատիկական ու ֆայլային նոր ենթածրագրերով։


## Ճիշտ և սխալ ծրագրերը

Մինչև հիմա մի քանի անգամ հանդիպեցինք «բառային», «շարահյուսական» և
«իմաստային» բնորոշումներին։ Ժամանակն է դրանք հստակ իրարից տարբերել։

_Բառային սխալի_ դեպքում ծրագրի նիշերից հնարավոր չէ Կեռասի ճիշտ բառային տարր
կազմել։ Օրինակ՝

```basic
LET value = 3.
```

Մեր թվային հաստատունի կանոնով կետից հետո գոնե մեկ թվանշան է պահանջվում։ Նույն
դասի սխալ է առանց փակող չակերտի տեքստը կամ լեզվին անհայտ `@` նիշը։ Այս
սխալները հայտնաբերում է scanner-ը։

_Շարահյուսական սխալի_ դեպքում բոլոր առանձին բառային տարրերը ճիշտ են, բայց
դրանց հաջորդականությունը չի համապատասխանում քերականությանը․

```basic
IF value > 0
    CALL Print value
END IF
```

Այստեղ `IF`-ի պայմանից հետո բացակայում է պարտադիր `THEN` բառը։ Այսպիսի
սխալները գտնում է parser-ը։

_Իմաստային սխալի_ դեպքում տեքստը ճիշտ բառերից կազմված և քերականորեն ճիշտ
ծրագիր է, բայց խախտում է անունների կամ տիպերի կանոնները․

```basic
SUB Main
    DIM value AS REAL
    LET value = FALSE
END SUB
```

Parser-ը հեշտությամբ ծառ կկառուցի այս ծրագրից։ Միայն իմաստային վերլուծիչը
կպարզի, որ `REAL` փոփոխականին փորձ է արվում `BOOL` արժեք վերագրել։ Նույն
դասին են պատկանում չհայտարարված անունը, կրկնակի հայտարարությունը, սխալ
արգումենտներով կանչը, ոչ տրամաբանական պայմանը և առանց արժեքի ավարտվող
ֆունկցիան։

Այս բաժանումը նաև ուրվագծում է մեր կոմպիլյատորի աշխատանքի հաջորդ փուլերը․

```text
նիշեր  ->  բառային տարրեր  ->  AST  ->  իմաստ ստացած AST
          scanner             parser   semantic analyzer
```

Իրական կոմպիլյատորը լավ ծրագրից մեքենայական կոդ ստանալուց բացի պետք է սխալ
ծրագրի մասին հասկանալի հաղորդագրություններ տա։ Այդ պատճառով բոլոր երեք
դասերի սխալներին հետագա զրույցներում առանձին ուշադրություն ենք դարձնելու։


## Մի ամբողջական օրինակ

Հիմա արդեն կարող ենք կարդալ մի քիչ ավելի մեծ Կեռաս ծրագիր։ Այն լրացնում է
թվերի զանգվածը քառակուսիներով, հաշվում դրանց գումարը և արդյունքը համեմատում
օգտագործողի ներմուծած սահմանի հետ։ Օրինակում կան լեզվի գրեթե բոլոր հիմնական
կառուցվածքները, բայց ոչ մի նոր կանոն։

```basic
' values զանգվածը լրացնել 1, 4, 9, ... թվերով
SUB FillSquares(values[] AS REAL, count AS REAL)
    FOR index = 0 TO count - 1
        LET values[index] = (index + 1)^2
    END FOR
END SUB

' հաշվել զանգվածի առաջին count տարրերի գումարը
SUB Sum(values[] AS REAL, count AS REAL) AS REAL
    DIM index AS REAL
    DIM result AS REAL

    LET index = 0
    LET result = 0
    WHILE index < count
        LET result = result + values[index]
        LET index = index + 1
    END WHILE

    RETURN result
END SUB

' ստուգել՝ արդյոք թիվը մեծ է տրված սահմանից
SUB IsLarge(value AS REAL, limit AS REAL) AS BOOL
    RETURN value > limit
END SUB

SUB Main
    DIM values[8] AS REAL
    DIM count AS REAL
    DIM limit AS REAL
    DIM total AS REAL
    DIM large AS BOOL
    DIM message AS TEXT

    LET count = 8
    CALL FillSquares values, count
    LET total = Sum(values, count)

    CALL Print "Ներմուծիր համեմատման սահմանը։"
    LET limit = NUM(Input())
    LET large = IsLarge(total, limit)

    IF large THEN
        LET message = "Գումարը մեծ է սահմանից։"
    ELSEIF total = limit THEN
        LET message = "Գումարը հավասար է սահմանին։"
    ELSE
        LET message = "Գումարը փոքր է սահմանից։"
    END IF

    CALL Print message
    CALL Print total
END SUB
```

Ծրագրի կատարումը սկսվում է `Main`-ից։ `values`-ը ութ թվերի զանգված է, որի
բոլոր տարրերը սկզբում զրո են։ `FillSquares` պրոցեդուրան զանգվածը ստանում է
հղումով և `FOR` ցիկլով փոխում նրա տարրերը։ `Sum` ֆունկցիան նույն զանգվածը
կարդում է `WHILE` ցիկլով ու վերադարձնում `REAL` արդյունք։ Այնուհետև `Main`-ը
տեքստ է ներմուծում, `NUM`-ով դարձնում թիվ, կանչում է `IsLarge` ֆունկցիան և
`IF` հրամանով ընտրում երեք հաղորդագրություններից մեկը։

Այս նույն ծրագրի կամ նրա առանձին հատվածների ճանապարհին դեռ կհետևենք։
Scanner-ը տեքստից կառանձնացնի `SUB`, `IDENT`, `REAL` և մյուս բառային տարրերը։
Parser-ը դրանցից կկառուցի ենթածրագրերի, հրամանների ու արտահայտությունների
ծառը։ Իմաստային վերլուծիչը `values`-ի ամեն կիրառություն կկապի ճիշտ
պարամետրի կամ հայտարարության հետ և կստուգի գործողությունների տիպերը։ Իսկ
կոդի գեներատորը վերջում այդ արդեն հասկացված ծրագիրը կդարձնի կատարվող կոդ։


## Կեռասի ամբողջ քերականությունը

Գլուխն ավարտեմ լեզվի քերականությունը մեկ տեղում հավաքելով։ Այստեղ նոր բան
չկա․ սա պարզապես նախորդ բաժիններում մաս-մաս քննարկված կանոնների ամբողջական
պատկերն է։ Հետագա աշխատանքում այն օգտագործելու ենք որպես scanner-ի, parser-ի
և AST-ի կառուցվածքի հենակետ։

```ebnf
Program = [ NewLines ] { Subroutine NewLines } EOF.

Subroutine = 'SUB' IDENT
             [ '(' [ ParameterList ] ')' ]
             [ 'AS' TypeName ]
             Sequence
             'END' 'SUB'.

ParameterList = Parameter { ',' Parameter }.
Parameter = IDENT [ '[' ']' ] 'AS' TypeName.

TypeName = 'BOOL' | 'REAL' | 'TEXT'.

Sequence = NewLines { Statement NewLines }.
NewLines = NEWLINE { NEWLINE }.

Statement = Dim | Let | If | While | For | Call | Return.

Dim = 'DIM' IDENT [ '[' Expression ']' ] 'AS' TypeName.
Let = 'LET' IDENT [ '[' Expression ']' ] '=' Expression.

If = 'IF' Expression 'THEN' Sequence
     { 'ELSEIF' Expression 'THEN' Sequence }
     [ 'ELSE' Sequence ]
     'END' 'IF'.

While = 'WHILE' Expression Sequence 'END' 'WHILE'.

For = 'FOR' IDENT '=' Expression 'TO' Expression
      [ 'STEP' [ '+' | '-' ] NUMBER ]
      Sequence 'END' 'FOR'.

Call = 'CALL' IDENT [ ExpressionList ].
Return = 'RETURN' Expression.

ExpressionList = Expression { ',' Expression }.

Expression = Disjunction.
Disjunction = Conjunction { 'OR' Conjunction }.
Conjunction = Negation { 'AND' Negation }.
Negation = { 'NOT' } Equality.
Equality = Comparison [ ('=' | '<>') Comparison ].
Comparison = Addition [ ('>' | '>=' | '<' | '<=') Addition ].
Addition = Multiplication { ('+' | '-' | '&') Multiplication }.
Multiplication = Power { ('*' | '/' | '\' | 'MOD') Power }.
Power = Unary [ '^' Power ].
Unary = { ('+' | '-') } Subscript.
Subscript = Factor [ '[' Expression ']' ].
Factor = 'TRUE' | 'FALSE' | NUMBER | STRING
       | IDENT [ '(' [ ExpressionList ] ')' ]
       | '(' Expression ')'.
```

Այսպիսով, Կեռաս լեզվի բազային տարբերակի սահմանները որոշված են։ Հաջորդ
զրույցներում արդեն կառուցելու ենք այս կանոններն իրականացնող կոմպիլյատորը։
